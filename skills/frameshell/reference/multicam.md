# Conversation with several people: multicam

A podcast, interview, panel or recorded call with one file per person (video with its own sound), a set of cameras with separate recorders, or one gallery-view call recording with everyone in tiles ([below](#a-gallery-view-call-recording)). A **multicam group** syncs the files (**angles** for pictures, **mics** for separate sound); a **program track** holds one **shot** per stretch of time (`solo`, `two-up`, `grid`, and `screen` or `pip` for a screen share) and switches pictures only: every sound of the group plays under every shot. `frameshell direct` proposes the shots from who speaks, by rules; you review the doubtful ones; the human corrects in the editor. Commands assume the session rule of [SKILL.md](../SKILL.md); every flag is in [cli.md](cli.md).

## Steps

1. **Orient.** `frameshell timeline show --json`: a group exists when `groups` is set and a `program` track is there; then skip to step 4 (the human may have started it). Otherwise `frameshell import <file…> --wait`, one file per person, each with sound.
2. **Create the group.** One transaction: `frameshell multicam create assets/ana.mp4 assets/ben.mp4 --name Ana --name Ben --group-name interview --json`. The files are synced by audio against each other. Names in file order; ask who is who when the file names do not say. **Cameras with separate mics:** list the cameras, then every sound file with `--mic-file`, and say which sound each camera carries with `--sound` (one per camera, in order: a mic number, `none` for a wide camera with no mic, `camera` for its own file): `frameshell multicam create assets/wide.mp4 assets/ana.mp4 assets/ben.mp4 --name Wide --name Ana --name Ben --mic-file assets/ana.wav --mic-file assets/ben.wav --mic-name Ana --mic-name Ben --sound none --sound 1 --sound 2`. Ask who wears which mic when the file names do not say; one mic for two people is `--sound 1 --sound 1` (they speak together for `multicam turns` until the mic's transcript has speakers: see [One mic for several people](#one-mic-for-several-people)).
3. **Check the sync before anything else.** The output has one confidence per file. Below 0.5 the file got no shared sound to match, was **not** shifted, and `warning:` says so (no sound at all, or separate recordings that do not hear each other, as with a remote call). Do not trust a high one blindly either: look at a clap or a laugh, `frameshell frame --at <s> --out <file.png>` and `multicam turns` should agree on who talks. Fix a wrong angle with `frameshell multicam offset <group> <angle> <seconds>`, a wrong mic with `frameshell multicam mic <group> <mic> --offset <seconds>` (the group second where that file's time 0 plays; to start one earlier, raise the others), then check again. Each file reports which file it matched (`against`): a mic that matched only one faint camera is worth a listen. Only the first 10 minutes of each file are matched.
4. **Cut the silences first.** Cut over the program track, before directing, so the director sees the final length. A silence is a stretch where no angle has a turn: `frameshell multicam turns <group> --json` gives `turns: [{angle, name, start, end}]` sorted by `start` on the group clock; the gaps between the latest `end` so far and the next `start` longer than the person wants (default 0.7 s, as in [transcript-editing.md](transcript-editing.md#choosing-cuts)) are the candidates. Before any cut, the timeline clock of the single first shot equals the group clock; cut from `end + 0.1` to `start - 0.2`, last range first, in one transaction. `cut` ripples the program track and snaps into pauses of every angle's sound; read `snaps` as in transcript-editing.md. Skip this step when the person did not ask for it.
5. **Pick a template.** Ask when the person did not say; it only sets the defaults:

   | Template | For | Shot length | Cutaway |
   |---|---|---|---|
   | `interview` (default) | Two or three people, one asking: long solos on answers, few two-ups | 2.5 to 20 s | to the listener, 3 s |
   | `podcast-calm` | Relaxed talk: long holds, two-ups on banter | 4 to 30 s | to a wide, 4 s |
   | `panel-dynamic` | Several people trading quickly: short shots, frequent reactions | 1.5 to 10 s | to the listener, 2 s |

   Tune only what the template misses in `director.json` at the project root (`template`, `minShot`, `maxShot`, `cutLead`, `twoShot`, `wide`, `cutaway`, `screen`, `weights`; null switches off `maxShot` (no cutaways) and the `twoShot`/`wide` times, `cutLead: 0` cuts on the first word; `weights` per angle id, 0 = never shown alone, e.g. a host who should not hog the picture). Edit the file like any project file you own; `--rules <file>` takes another one for a try.
6. **Direct.** `frameshell direct <group> --json` is one operation and so one undoable step; wrap it in a transaction when it belongs with the cuts. Pass `--template <id>` only when `director.json` does not name the chosen template, because the flag replaces the file's `template`. Same turns and rules give the same shots, so changing a rule and re-running is the way to adjust, not editing shots one by one. `--from`/`--to` (timeline seconds) direct a range only.
7. **Review the low shots.** `low` in the `--json` output lists the shots below 0.5 confidence: `{clip, start, end, shot, angles, confidence, reason}`. The rules cannot see what the words mean, so look at each with the transcript:
   - `frames_strip { from, to, count }` (MCP) or `frame --at <s> --out <file.png>` for the picture; read the words said there (`frameshell://transcripts/{file}`, or `transcripts/<file>.words.json`: word `start`/`end` are source seconds of **that angle's file**; its timeline time is the shot's `start` plus `(offset + word.start) - shot.in`, with `offset` of the angle and `in` of the shot, both on the group clock). Transcribe a file only when none exists: `frameshell transcribe assets/<file> --language <code>`.
   - Fix with `frameshell shot set <shot> --angles <angle>` (or `--layout`): hold a reaction after a punchline, show the listener on a question, a two-up while two people finish each other's sentence. To change part of a shot, `frameshell clip split <shot> --at <s>` first.
   - Leave a low shot alone when it looks right; its `reason` says what the rule saw. A shot you change with `shot set` loses `confidence` and `reason`; the next `direct` hands it back to the director (only the app's own edits are the person's).
   Put the review in one transaction named in the person's words, then look at the result as a whole: `frames_strip` over the full length.
8. **Vertical (9:16), when asked.** A 9:16 export of 16:9 cameras keeps a narrow strip of each picture in a solo (a wider one per tile in a two-up, stacked), centered unless the angle is **reframed**. For each angle shown in solos or two-ups: `frameshell frame --at <s> --out <file.png>` at a moment that angle shows, find the face (fraction across the picture: 0 left edge, 1 right edge), then `frameshell multicam reframe <group> <angle> --time <s> --x <fraction>` (`--y` only when the face is high or low in a picture taller than the tile). One key holds for the whole recording; add a key where the person moves (the point glides in a straight line between keys, so put two keys close together for a quick move) and `--remove` a wrong one. Keys live on the group clock, so later cuts and `direct` keep them. Check with `frameshell frame --at <s> --out <file.png> --preset vertical-1080x1920` on a few solos per angle. A `screen` shot and the screen of a `pip` are never cut. Face detection is not available: look at the frames.
9. **Export and verify.** `frameshell render --preset youtube-1080p --json` (`vertical-1080x1920` for 9:16, after step 8), first transcribe every angle file that has no current transcript (`frameshell transcribe assets/<file> --language <code>`), then `frameshell transcribe --verify exports/<file>.mp4 --json`. Done = `lost` empty, `unchecked` empty (no warning that no clip could be checked), every `uncertain` word reviewed as in [transcript-editing.md](transcript-editing.md), and the person has the export path and the transaction ids.

## Rules

- **Never overwrite the human's shots.** Shots chosen in the app (a `shot.set` by author `ui`, and pieces cut out of them) are kept by `direct`; do not pass `--replace-human` unless the person asked to start the cutting over. After "continue", read `history --since <resume point>` as in SKILL.md, then re-run `direct` (over a range if they only fixed part): it keeps their fixes and redoes the rest. Never `shot set` over a shot whose last change is theirs.
- **Do not add or delete shots by hand.** The program track is filled by `direct`; changing one is `shot set`, and `clip split`/`trim`/`move`/`remove` work on shots but a gap leaves the picture empty. Adding shots to a program track is not supported yet.
- **Late cuts are fine, late sync is not.** `cut` and `clip trim --ripple` keep the angles in sync (the program track ripples with every other track). `multicam offset` is refused when a shot would play past the group's new end (the longest camera; a mic never extends it): trim it first. After changing an offset, run `multicam turns` and `direct` again.
- **Gain levels the mics.** When one voice sounds in another person's mic, `multicam angle <group> <angle> --gain <dB>` evens the levels and `multicam turns` counts it (for an angle that takes a separate mic, `multicam mic <group> <mic> --gain=<dB>`: levels belong to the mic); mute a mic that carries only noise with `--muted`. Move an angle to another mic with `multicam angle <group> <angle> --mic <mic id>` (`camera` = its own file, `none` = no sound). Check the turns again after.
- **Screen shares.** A recording of a shared screen is an angle like the others (`multicam create`, it needs no sound but is then left unsynced with a warning: fix it with `multicam offset`). Mark it with `frameshell multicam angle <group> <angle> --screen`: `direct` then never shows it as a person and, where its picture moves for `screen.motion` seconds (a slide, a scroll, a demo; `screen.threshold` is how much), cuts to `screen` while nobody speaks and to `pip` (screen, speaker in an inset in `screen.corner`) while someone does. Tune `screen` in `director.json` (`motion` null = never, `pip: false` = screen alone). A static screen stays out of the picture; to hold it anyway, `shot set <shot> --layout screen` (or `pip --corner top-left`). Review low `screen` shots like the others.
- **Not covered yet.** Adding or removing a mic of an existing group (make the group again, or edit the timeline file); one group that switches tile crops when a call's layout changes.

## A gallery-view call recording

One Zoom, Meet or Teams recording in gallery view (everyone in a tile of one picture, one mixed sound track) instead of one file per person:

1. **Make the group.** `frameshell import assets/call.mp4 --wait`, then `frameshell multicam gallery assets/call.mp4 --json`. It finds the tile grid by its gutters (lines of one flat colour between tiles) on frames spread over the whole file and adds one angle per tile, each a crop of the same file, in reading order (rows top to bottom, each left to right), plus the program track and a `grid` shot. Run it once: every run adds another group and program track, and decodes the whole file again. Then ask who sits in which tile and name each one with its angle id from `tiles`: `frameshell multicam angle <group> <angle> --name Ana`. Pass `--name` once per tile on the first run only when you already know the tile count; a wrong count is refused. The call's sound plays once, through the group mic `call` (`frameshell multicam mic <group> call --gain=<dB>` sets its level). No sync step: every tile is the same file.
2. **Check the tiles.** `tiles` has each angle's `crop` and `confidence` (0 to 1). Below 0.5 a `warning:` names the tile. `frameshell frame --at <s> --out <file.png>` shows the grid shot; a tile that shows a gutter, a name label or half of another person needs a fix: `frameshell multicam angle <group> <angle> --crop-left <f> --crop-top <f> --crop-right <f> --crop-bottom <f>` (fractions of the whole recording's picture). Speaker view or a single camera has no grid: the command refuses it.
3. **Layout changes.** `layouts` lists the stretches of the call with their tile count; more than one means someone joined or left, or a screen share replaced the gallery, and a `warning:` gives each time. The angles follow the layout held longest (`used: true`). Tell the person the times. When the part that matters has another layout, make its own group with `--at <s>` (a second of that stretch) and cut away the rest. That adds a second group and program track above the first, which hides it: when the new group replaces the old one, `frameshell revert <op>` the first `multicam gallery` operation (or `frameshell track remove <track> --force` its program track); otherwise check the tiles in the other stretches and fix crops, or cut those stretches out.
4. **Who speaks.** Every tile hears the one mixed track, so until its transcript has speakers they all speak together. Run [One mic for several people](#one-mic-for-several-people) on `assets/call.mp4` (`frameshell transcribe --speakers assets/call.mp4 --people <tiles>`), set each tile's `--speaker`, then continue from step 4 of the [Steps](#steps).

## One mic for several people

When people share a mic (one recording of the room, a mixed track, each camera hearing everyone, or one separate mic several angles take with `--mic`), mic energy cannot tell who speaks. The words can:

1. Work on the file the angles are heard through: the shared camera file, or the shared mic's `asset` (`timeline show --json`, `groups[].mics`). `frameshell transcribe assets/<file> --language <code>`, then `frameshell transcribe --speakers assets/<file> --people <n> --json`. Ask how many people talk when you do not know. Read a few words of each speaker (`transcripts/<file>.words.json`, `speaker` on each word) and rename them to the people in its `speakers` list (`name`; keep the `id`).
2. Tell each angle whose voice it is: `frameshell multicam angle <group> <angle> --speaker s2`. Angles that hear the same file, or the same mic once its transcript has speakers, take their turns from its speakers anyway (screen angles never do; two cameras of one person on one mic: give both the same `--speaker`); without `--speaker` they take the free speakers in order and `multicam turns` warns about the guess, so set them.
3. `frameshell multicam turns <group> --json`: `speakers` lists the angles measured from words; then direct as usual. A word said by the wrong person is corrected in the transcript's `edits` (`{ "w_000042": { "speaker": "s1" } }`) or by the person in the app's transcript view; re-run `multicam turns` and `direct` after.

## Correcting who speaks

Measured turns are wrong sometimes: a laugh heard as speech, one person's mic bleeding into another's, a diarized word given to the wrong person. A person's correction always wins over the measurement:

- **A whole stretch, by time:** `frameshell multicam paint <group> <angle> --from 12 --to 15.5 --speaking --alone` (group seconds, as `multicam turns` reports them). `--silent` removes the angle's turn there; `--measured` (without an angle for all of them) takes a range back. The marks are `groups[].painted` and `direct` obeys them, also on the next run. The person paints them in the app, on the program track's turn lanes.
- **Words, by the transcript:** the person selects words in the transcript view and sets their speaker (also a new one, or a renamed speaker); that is an `edits` entry of the transcript file, which survives `transcribe --speakers` re-runs. Which speaker an angle is: `multicam angle --speaker`, also set from the angle panel of the shot inspector.
- After either, run `multicam turns` again and `direct` over the range; shots the person chose are kept (`direct` reports them).

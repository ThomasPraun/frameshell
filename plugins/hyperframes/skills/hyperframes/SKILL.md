# HyperFrames clips

A `hyperframes` clip is an HTML page rendered headlessly to VP9 WebM with alpha, then layered over the footage below it. The daemon renders it in the background and caches the result. Until the render is ready, the human's preview plays the page itself, live at the playhead and labelled "Live". It does so when the clip is the topmost picture; otherwise the preview shows a progress slate. The render, not the live page, is what export uses.

## Steps

1. Scaffold: `frameshell hyperframes new <name> [--template <id>] [--duration <s>]` writes `compositions/hyperframes/<name>/index.html` at the project resolution. Edit that file. For titles, headlines, lower thirds, lists, counters, odometer wheels, slot-machine rolls, tab bars, a freeze on the beat, end cards, a cursor clicking or dragging, an app window, a glass card, a prompt bar that types and a 3D product shot start from a template (see [Motion templates](#motion-templates)); the plain scaffold is a CSS-animated card.
2. Check it: `frameshell hyperframes check [<composition>]` (see [Check](#check)). Run it after every edit of a composition and before you wait for a render: a lint error found here costs a second, the same mistake found by a failed render costs minutes.
3. Add the clip on a video track above the footage:
   `frameshell clip add <track> --type hyperframes --source compositions/hyperframes/<name>/index.html --start <s> --duration <s> [--props '{"title":"Launch"}']`
4. Wait for the render: `clip.renders` (MCP `clip_renders`) until the clip's `state` is `ready`. `failed` carries the render error in `error`: fix the composition, run `check` again. A 1440p clip renders in about 2x its real length.
5. Check the result with `frame_capture` / `frameshell frame --at <s>` at a time the clip covers.

Done = `check` passes, every hyperframes clip is `ready` and a captured frame shows it where intended.

## Motion templates

`frameshell hyperframes new <name> --template <id>` scaffolds a motion composition: a page painted by the Frameshell motion runtime (springs, role eases, stagger), a pure function of time, so render, live preview, Pick and element mode agree. - **Over footage or alone.** `kinetic-headline`, `lower-third`, `logo-lockup`, `checklist`, `comparison`, `counter`, `number-wheel`, `slot-roll`, `tab-indicator`, `big-word`, the four `cursor-*` templates, `typing-field`, `comment-box`, `terminal`, `chat-bubble`, `notification-stack`, `prompt-bar`, `glass-card`, `product-shot`, `logo-3d`, `emphasis-marker`, `pip-card`, `work-cards`, `light-leak`, `orbit`, `locked-on`, `spotlight`, `phone-fan` and the three `code-*` templates are transparent, to layer over a video track (`light-leak` goes on a track above and across a cut, about a second long, so the cut keeps its length). The ones with `bg` and `backdrop` props (`logo-lockup`, `checklist`, `comparison`, `counter`, `number-wheel`, `slot-roll`, `tab-indicator`, the `cursor-*` ones, `typing-field`, `comment-box`, `terminal`, `chat-bubble`, `notification-stack`, `work-cards`, `prompt-bar`, `product-shot`, `logo-3d`, `emphasis-marker`, `orbit`, `phone-fan` and the `code-*` ones) become a solid card for a film made of generated clips when you raise `backdrop` toward 1. `end-card`, `app-window`, `device-frame`, `before-after`, `pull-back-reveal`, `freeze-cut`, `logo-sting` and `scene-background` always paint their own background; put `scene-background` on a track under the others.
- **Code (`code-typing`, `code-diff`, `code-morph`).** The code is a prop with real line breaks (`clip set --props '{"code":"a = 1\nb = 2"}'`; JSON `\n`). A small built-in tokenizer colours keywords, strings, numbers, comments and calls of `js`, `python`, `shell` and `json` one line at a time (a string or block comment that runs over several lines is coloured line by line); no network and no highlighter library. The face is the system monospace (`style.json` has no monospace role), the window colour and accent come from `colors.card` and `colors.accent`, and the type shrinks until the longest line and every row fit, measured on the machine that renders. `code-diff` matches whole lines by exact text, so a re-indented line is one removed and one added line.
- **Glass cards (`glass-card`, ADR 0031).** The template paints only the glass look (a translucent tinted card, hairline border, light top edge, a shine pass); the blur, saturation and dark scrim under it are the clip's backdrop, so a card on a track above the footage is two steps: `frameshell clip add <track> --type hyperframes --source compositions/hyperframes/<name>/index.html --start <s> --duration <s>`, then `frameshell clip set <clip> --glass` (copies `style.json` `glass`: blur 46, saturate 1.45, dim 0.55; `--backdrop-dim 0.72` over bright footage). Glass is a style choice, never a default: use it when `style.json` `glass.cards` is true or the person asks. The backdrop covers every pixel of the render whose alpha is above about 3 %, so keep `tintOpacity` at 0.06 or more and `shadow` at 0 unless a soft halo of glass round the card is wanted. Without `--glass` the card is only a pale pane. On the bottom picture track the backdrop is not drawn. Empty or too long texts never break the picture: an empty line is dropped and a long text shrinks to fit.
- **Word behind the person (`big-word`, ADR 0032).** Put the clip on its own video track above the footage track, then `frameshell track set <word track> --behind <footage track>`. Export, `frameshell frame` and the app's preview draw the word between the background and the person (the preview shows it in front with a note until the matte is ready; the track header shows the progress); the footage's subject matte is made when missing, so run `frameshell matte <asset>` first to start at once. The recipe (cover, face, shots to skip) is in the frameshell skill's reels page. Keep the word 30 to 55 % covered by the person and off the face (`place` and `size` move it), skip two-person shots, and put b-roll above the word's track. `--behind none` puts the word back on top.
- **The cursor is a carrier (`cursor-*`, `app-window`, `typing-field`, `comment-box`).** It is 4 to 7 % of the short side (`cursorSize`), starts outside the frame so it never fades in, travels on arcs with an ease in and out and a tiny overshoot, may hesitate before its target (`hesitate`), presses to 0.84 in 0.1 s and back in 0.22 s, and the thing it clicks reacts on that very frame: the click causes the next beat, never the other way round. After the click it drifts aside and keeps drifting. Travel time follows distance, so the click lands a second or so in; make the clip at least 4 s so the reaction is seen. A clip too short never loses the reaction: the cursor first gives up its hesitation, then moves up to 2.2 times faster, and a typed line (`typing-field`, `comment-box`) is typed up to 9 times faster with a shorter progress line, so the click and the result still show before the exit (a clip shorter than about a second cannot hold any of them). With `camera` set to `follow` (`cursor-click`, `app-window`) the click is on the same frame as without it; the zoom never shows the scene's edge, and a live preview scrubbed through the zoom may differ from the export by an edge pixel of a scaled shape. To change what is clicked, change the props, not the HTML. The paragraph of `cursor-text-select` is measured from layout, so a phrase that wraps still gets its highlight and its drag on the real words.
- **Props are typed.** Change them with `frameshell clip set <clip> --props '{"headline":"Ship it","keyword":"Ship"}'`: a client revision is one `clip set`, never an edit of the HTML. A number outside its range is clamped, a bad colour or enum value falls back to the default, so a wrong prop never breaks the picture. Use `#rrggbb` colours.
- **Brand tokens.** When `style.json` exists the template takes colours (`colors.bg`, `ink`, `accent`), fonts (`fonts.display`, `ui`; a font file under `assets/fonts/` is copied into the composition and declared with `@font-face`) and `brand.product`, `brand.cta`, `brand.url` as the defaults of its props, at scaffold time. Later edits of `style.json` do not reach a scaffolded composition's props: change the props, or scaffold again. Without a style the template keeps placeholder defaults: ask the person for real ones.
- **Brand pictures.** `frameshell hyperframes new closer --template logo-lockup --component assets/brand/acme-com/logo-1.svg` fills the template's picture prop (for example `logo` of `logo-sting`, `image` of `pip-card`) with a file `frameshell brand show` lists (a captured logo or section crop, a Figma frame); `before-after` has two, so name the prop: `frameshell hyperframes new ba --template before-after --component before=<path> --component after=<path>`. The file is copied into the composition and becomes the prop's default (`logo-3d` extrudes only an SVG: pick an `svg` file of the list, not a raster). Only files of `brand.json` are taken; list the findings to the person and confirm the brand before using them (the Frameshell skill's brand page).
- **Style variables.** With a `style.json`, every render and live page also gets the style as CSS variables in a first stylesheet (`var(--fs-color-accent)`, `var(--fs-font-display)`, `var(--fs-motion-standard)`, ...; the list is in the Frameshell skill's project model, Style). In a hand-written composition use `var(--fs-color-accent, #ff5a1f)`, always with a fallback, so a later `style set` reaches it; editing a value re-renders the clip.
- **Layout per format.** The layout reads the composition's `data-width` / `data-height` through `M.pick(wide, square, tall)`, so one composition lays out for 16:9, 1:1, 4:5 and 9:16; the scaffold uses the project resolution, and a render for a format of another aspect (`frameshell format add 9x16`, then `render --formats`) sets the root to that format's size first.
- **Frozen runtime.** The scaffold copies `frameshell-motion.js` into the composition directory, so a plugin upgrade never changes an existing clip's pixels. `frameshell hyperframes update [<composition>] [--dry-run] [--force]` refreshes older copies on request (clips that use one render again); an edited, newer or foreign copy is kept unless `--force`.
- Edit the generated `index.html` for anything props cannot say; keep the rules below.

## Motion compositions (written by hand)

A composition that calls `FrameshellMotion.bind("<composition id>", paint)` has no GSAP timeline: the page is painted at time `t` by `paint(t)`, and every frame must depend on `t` alone.

- Load `<script src="frameshell-motion.js"></script>` in the head and call `bind` synchronously from the composition's script. The root must not carry `data-no-timeline`.
- `M.write(element, { x, y, rotate, scale, scaleX, scaleY, opacity })` is the only way to move an element: it writes a 2D `transform` and `opacity`. Spring and ease the numbers: `M.spring("heavy" | "default" | "snappy" | "playful", t - start, from, to)`, `M.ease("enter" | "snap" | "pop" | "camera" | "exit" | "progress", fraction)`, `M.stagger(i, n, M.STAGGER_STEPS.words)`, `M.track(...)` for values that retarget.
- Presets by role: snappy for buttons and pills, default for cards and camera, heavy for big type and logos, playful for mascots only. Position and size may overshoot; opacity and colour never spring.
- `M.props()` returns the clip's props as typed values from `data-composition-variables`; declare number props with `min` and `max` and colour props as `#rrggbb`.
- Never write `transform` yourself and never set `filter` on the `html` element (the runtime changes it on every seek so Chrome repaints the whole page). Chrome does not repaint a move under about 1/80 px, so a hand-written slow drift renders differently depending on the frames painted before it; `M.write` keeps every step at 1/32 px or more. Do not nest moving elements in a container scaled below 0.4, where those steps are too small again.
- Never use CSS `transition` or animation, timers, `requestAnimationFrame`, `Date` or `Math.random` (seeded noise only), and no `will-change`, `translate3d` or any 3D transform. Never set the `translate`, `scale` or `rotate` CSS properties: element adjustments (the Elements inspector) own them and compose with the runtime's `transform`.
- Fonts and images ship inside the composition directory and are known before frame 0; a fallback font is a bug. Do not measure text in script (`getBoundingClientRect` lies under a scaled ancestor): lay out with CSS.
- Holds never stop: give a held graphic a slow drift or push of a few percent. Prefer solid or radial backgrounds over long dark linear gradients (they band in H.264), and accents at 15 % opacity or more.
- **Motion blur** (`frameshell clip set <clip> --motion-blur`) renders each frame as the average of 8 pictures at times around it. A composition that hard-cuts between scenes inside itself declares every cut, or the frame on the cut blends both scenes: `var guard = M.cuts([2.5, 6]); M.bind("intro", function (t) { t = guard(t); ... });`. It changes nothing without blur. Needs runtime 0.4.0 (`frameshell hyperframes update`). A GSAP or CSS composition has no guard: with blur on, keep its cuts out of it (split it into clips that butt on the timeline).
- **On the beat.** Put `<meta name="frameshell-timing" content="beats markers">` in the entry's `<head>` (ask only for what the composition uses) and read `window.frameshellTiming` in its script: `beats` (`{ at, beat, bar? }`, `bar` set on a bar start), `tempo` (`{ bpm, meter }`) and `markers` (`{ at, id, label, color? }`), only those inside the clip, in composition seconds (the `t` of `paint(t)`). Land a hit on its time with the lead the motion needs (`M.spring` settles after the hit, so start a move before it); fall back to fixed times when `beats` is empty (`beatsProblem` says why, as a code: `no-tempo`, `no-music-clip`, `no-beats` (not measured yet), `broken-beats`, `low-confidence`). Only such clips render again when the music, the tempo or a marker moves, or when the clip moves along the music; others never do. **Runtime 0.5.0 reads it for you** (pure functions of `t`, so seeks stay exact; a clip scaffolded earlier keeps its 0.4.0 copy until `frameshell hyperframes update`): `M.beats(nominal?)` lists the clip's beats `{ at, index, beat, bar? }`; `M.beatAt(t, nominal?)` gives `{ index, beat, bar, phase }` (`index` 0 is the clip's first beat, negative before it, `beat` and `bar` are the numbers `beat:N` and `bar:N` use, `bar` is null when no bar start is inside the clip, `phase` 0 to 1); `M.beatTime(n, nominal?)` is the second of beat `n`; `M.sinceBeat(t, n, nominal?)` is `t` minus that second (negative before the beat: feed it to `M.ease` or `M.spring`); `M.springOnBeat(preset, t, n, from?, to?, nominal?)` is `M.spring` started on beat `n`; `M.markers(label?)` lists the clip's markers (label match ignores case and spaces; `[]` without `markers` timing). `n` counts the clip's own beats from 0, and beats before the first or after the last continue at the nearest period. Without a usable grid (no meta tag, or `beatsProblem` set) they use `nominal`, `{ bpm, offset?, meter?, duration? }` (beat `n` at `offset + n * 60 / bpm`), or with none the clip's own seconds, one beat a second, so a composition passes the pace its props already say and looks the same without music. `M.hasBeats()` says whether the timeline's grid is in use and `M.frameshellTiming()` returns the raw object (`beatsProblem` included). The `checklist` template does this with `onBeats`: set the prop and add the meta tag with `beats` to its entry, and the ticks land on the first beats at or after `tickStart`; the tag is not scaffolded so a checklist never renders again when the music moves unless you ask.
- Frameshell templates carry no GSAP. For a composition you write for the person you may still use GSAP under the rules below.
- Verify before you trust it: `frameshell clip verify <clip>` (MCP `clip_verify`) captures 12 frames of the clip twice, cold and after seeking elsewhere first, and fails above 2/255 on a channel, naming the worst time, pixel and element. A difference means the composition keeps state between frames (see the rules above); the single warning "every probe frame is the same picture" means the timeline is not bound to the seek.

## 3D compositions (three.js)

How to make a 3D shot look right (studio defaults, materials, glint, camera, beat sheet, failure and fix, a GLB from Blender) is the [3D product shot playbook](3d-playbook.md): read it before building one.

A 3D template (`product-shot`, `logo-3d`) paints a three.js scene into one `<canvas>` on the motion runtime's clock. The scaffold copies the pinned three.js bundle (`frameshell-three.js`, MIT) next to `frameshell-motion.js`; `hyperframes update` refreshes both. Never load three.js from a CDN or `node_modules`: the render is offline and only files of the composition directory are cache inputs.

- **One clock.** `M.bind(id, function (t) { pose(t); renderer.render(scene, camera); })`: set every position, rotation, light and camera from `t`, then render once. `check` blocks `setAnimationLoop` and `THREE.Clock` / `getDelta`, and warns on `mixer.update(dt)` (use `mixer.setTime(t)`).
- **Assets before frame 0.** Load models and textures from inside the composition directory and hand the promise to `window.__hf.buildReady.<key>`: the render (and the live page) waits for it, and a failed load fails the render with the path. `THREE.DefaultLoadingManager` holds nothing. GLB models must be plain glTF binary: no Draco, KTX2 or Meshopt compression. The bundle adds `THREE.RoomEnvironment`, `THREE.RoundedBoxGeometry`, `THREE.GLTFLoader`, `THREE.SVGLoader`, `THREE.FontLoader` and `THREE.TextGeometry` to the core classes; there is no `TTFLoader`.
- **Software renderer.** Renders use SwiftShader (no GPU), one clip at a time, about 0.1 to 0.3 s per 1080p frame for the product shot: a 6 s clip takes a minute or two. Soft shadows (VSM) are the cost: keep a 1024 shadow map, radius about 8 and 8 blur samples, never a 4096 map. Antialias with the renderer's `antialias: true`; render with `alpha: true` and a transparent clear so the clip keeps its alpha.
- **Motion blur is capped at 8 samples.** A composition that draws with WebGL (it holds `frameshell-three.js`, or a script makes a three.js WebGL renderer or a `webgl` context) renders `clip set --motion-blur` with at most 8 samples per frame, whatever `--motion-blur-samples` says (the default is 8): every sample is a full software-rendered frame, so 16 or 64 would take minutes per second of film. The render says so, and `frame`, `review` and export jobs repeat it in their `warnings`. Keep 3D blur for fast camera or product moves; a slow push-in gains nothing from it.
- **Element mode sees one canvas.** Pick and the Elements inspector can move or scale the whole 3D picture, not one object in it: object changes are props (`clip set --props`).
- The live preview in the app runs WebGL on the GPU; small shading differences from the export are normal. Judge with `frame_capture` once the clip is `ready`, and run `frameshell clip verify <clip>` on every 3D shot.

## Check

`frameshell hyperframes check [<composition>] [--strict] [--json]` lints compositions in the daemon, offline, with the HyperFrames linter (`@hyperframes/lint`) plus the seek-safety rules below. `<composition>` is a name from `hyperframes new` (`intro`), a composition directory, or an HTML entry such as `compositions/hyperframes/intro/index.html`; with none it checks every `compositions/hyperframes/<name>/index.html` (pass the path for a clip `source` kept elsewhere).

- Each finding is `file:line:column  severity  rule  message`, with a `fix:` line. `--json` returns `{ output, data, failed }`: `data.findings` per composition carry `file`, `line`, `column`, `rule`, `severity`, `message`, `fix`.
- Errors block: exit 1 (`failed: true`). Warnings do not, unless you run `check --strict`. Fix every error; read each warning and fix it unless you meant it.
- Use `check`, never `npx hyperframes`: the HyperFrames CLI renders and previews on its own, outside Frameshell's cache, ffmpeg and Chrome.

## Authoring rules

These are the rules that make a composition render the same on every frame and every worker. They follow the guidance of HyperFrames (Apache-2.0, github.com/heygen-com/hyperframes) in our own words; `check` enforces most of them.

- **One root.** The entry is one `index.html` with one `data-composition-id` root. Further scenes live in their own files, each wrapped in a `<template>`, and the root mounts them with `data-composition-src`. A file with timed content outside a `<template>` is a second root.
- **No selectors built from template literals.** `` gsap.to(`#${id}`, …) `` and the like hide the target from the checker and from the Pick tool: write the selector out, one tween per target (or a plain loop over a literal array).
- **Never animate layout.** `margin`, `padding`, `width`, `height`, `top` and `left` snap to whole pixels and stutter under a frame-by-frame seek. Animate `x`, `y`, `scale`, `rotation` and `opacity`.
- **Fonts are local.** (The `hyperframes new` scaffold uses a system font stack as a placeholder: replace it.) Declare each family with `@font-face` pointing at a file inside the composition directory. A system or web font changes between machines and between the live page and the render.
- **`fromTo` over a CSS start state.** Do not set a start transform in CSS and then tween to the end: a seek to the middle reads the CSS, not the tween. Write both ends in the tween: `tl.fromTo(el, { y: 40, opacity: 0 }, { y: 0, opacity: 1 }, 0)`.
- **No CSS `transition`, no `requestAnimationFrame`, no wall time.** The clock is HyperFrames', not the browser's.

### GSAP is sought, not played

The render and the live page set the paused timeline to a time (`tl.totalTime(t)`) instead of playing it. Write timelines that give the right frame wherever they are set:

1. One timeline, tweens placed with position parameters (`"<"`, `"<0.2"`, `"label+=0.3"`). No `delay` chains.
2. No ScrollTrigger: a clip does not scroll.
3. Stacked `from` / `fromTo` tweens on one property need `immediateRender: false` on the later ones, or a seek shows the wrong first frame.
4. Function-based values are evaluated at the first render, and each render worker starts fresh: never `Math.random()` or `gsap.utils.random()` (not even `gsap.utils.random(min, max, snap, true)`, which only returns a generator; the linter blocks all of them). Use fixed values, a hash of the element index, or a small seeded PRNG such as mulberry32 with a constant seed.
5. Never `repeat: -1`: give a finite repeat or an explicit duration.
6. No `onComplete`, `onUpdate`, `onStart` or DOM-reading callbacks: put the change in a tween.
7. Relative values (`"+=20"`) and `overwrite: "auto"` read state at the first render: prefer absolute values or `fromTo`.

Two judgement checks the linter cannot make: do not tween more than a third of the animated elements at once, and give a tween that travels more than a third of the frame an intermediate key so the motion reads.

## Composition rules

- One directory per composition. Every file in it counts: editing any file re-renders every clip using it; unchanged clips reuse the cache. Keep images, fonts and scripts (e.g. `gsap.min.js`) inside the directory so the render is offline and reproducible.
- The root element carries `data-composition-id`, `data-width`, `data-height` (the project resolution, from `frameshell.json`) and `data-duration` (seconds). The render is exactly that size and length, except in a format of the project with another aspect: there the render copy's root gets the format's `data-width` / `data-height`, so place and size things as fractions of them (read the root, or `M.stage()`), never fixed pixels, or the layout stays where it was in the bigger or wider frame.
- Timed elements carry `data-start`, `data-duration` and `data-track-index`. Animate with CSS animations or a paused GSAP timeline registered as `window.__timelines["<composition id>"]`; HyperFrames drives the clock, so wall time never applies. A composition with no GSAP timeline (CSS animations only, as the scaffold) carries `data-no-timeline` on its root; without it every render first waits 45 s for a timeline that never comes.
- Transparency: leave `html`, `body` and the root unpainted; the footage shows through. Backgrounds on inner elements (cards, panels) are kept, including partial alpha.
- Props are composition variables: declare each one with its default as an array on the root, `<html data-composition-variables='[{"id":"title","type":"string","label":"Title","default":"Title"}]'>` (`type`: `string`, `number`, `color`, `boolean`, `enum`, `font` or `image`), and read them with `window.__hyperframes.getVariables()`: the clip's `props` merged over the defaults. An object (`'{"title":"Title"}'`) is not a declaration; the render fails with the array to use instead. Changing `props` (`frameshell clip set <clip> --props …`) re-renders that clip only.
- Live preview serves the composition directory as it is, so the rules above also make the live page work: files inside the directory, a `[data-composition-id]` root, and no wall-clock animation. It runs in a sandboxed frame without `localStorage` or cookies. Fonts and timing can differ slightly from the render: judge the result with `frame_capture` once the clip is `ready`.
- The human can point at an element with the Pick tool: its `[frameshell] point` line names the element's selector and, when it lives in a `data-composition-src` sub-composition, that file (`in …`). `(created by a script)` means its id, classes and text are nowhere in that file: edit the script that builds it (GSAP, bindings), not the markup. Stable `id`s on elements you will want to change make picks easy to act on.
- Clip `in` is composition seconds shown at the clip's start; `duration` is how long it plays. Moving, trimming or changing `transform` (`--x --y --scale --opacity`) never re-renders.

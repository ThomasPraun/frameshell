# Premiere XML export: a derived xmeml file, export only, what is left out is said

#701 (follow-up of #383, epic #451) asks for the timeline as a Premiere Pro XML file, next to the OpenTimelineIO export of ADR 0045. SPEC decision 3 stands: the timeline JSON is the source of truth, the hand-off file is **export only**. The owner decided on 2026-11-19 (question Q3, every recommendation accepted): xmeml version 4, written by hand with no dependency; always absolute `file://localhost/` paths; dissolves in slice 1; the sound of video-track clips as linked audio clips; transforms, keys, speed ramps and grades named in warnings; no app menu in slice 1. **Slice 1 is built: CLI, MCP and daemon method. Slice 2 is built too: the app menu, a reader test, the Audio Levels filter (see "Slice 2" below).** The file has been checked structurally in this repo, read back by the `fcp_xml` adapter of OpenTimelineIO, and compared with the xmeml shape Premiere and Final Cut 7 are described to write; it has not been opened in Premiere Pro (no licence in CI), so the owner's first import is the real check.

## Context (verified)

- ADR 0045 built the OTIO converter: a pure module (`export/otio.ts`) plus `ExportService.otio`. It already says which clips mirror their sound (`mirrorsSound`, `soundMirrorName`) and that Premiere XML would read the same.
- `edgeTransitions` and `clipLength` (`packages/schema/src/transitions.ts`) are the one source of effective dissolve lengths and clip lengths; neither writer recomputes them.
- xmeml is the Final Cut Pro 7 interchange format. Premiere Pro imports it through File > Import. It places clips by absolute `start`/`end` frames (no gaps), links a picture to its sound with `<link>` elements, and writes a media path as a `file://localhost/` URL with a Windows drive as `C%3a`.

## Decision

1. **Export only, read-only, derived** (as ADR 0045 decision 1). `export.premiereXml` writes a file derived from the timeline, changes nothing (no transaction, not a `mutating` method, no proposal), and the file is never read back.
2. **Format.** `xmeml` version 4, one constant (`XMEML_VERSION` in `export/premiere-xml.ts`) so version 5 can follow. Written by hand as a small node tree printed once, with an `escapeXml` that also drops characters XML 1.0 cannot hold. No dependency. One `<sequence>` with `<media><video>` and `<media><audio>`, a sequence timecode, markers.
3. **Time.** Whole frames. `<rate>`: `timebase` = the whole rate, `ntsc` TRUE for 24000/1001, 30000/1001, 48000/1001, 60000/1001 and 120000/1001 (23.976, 29.97, 59.94...), FALSE otherwise. A rate xmeml cannot name (27.5) is written at the nearest whole rate with a warning that the times drift. Positions are `Math.round(seconds * fps)` of the start and of the end, as ADR 0045 decision 3 (`placeClip` in `export/handoff.ts`, one placement for both writers, built on `clipLength`); a clip ends at least one frame after it starts. Every `<rate>` in the file is the project rate, the file's own included: `in`, `out` and `duration` are all counted in project frames, so the file is internally consistent whatever the media's rate; Premiere conforms it on import. `in` is the source start, `out` is `in` plus the source the timeline length consumes at the clip's `speed`.
4. **Paths.** `<pathurl>` is always absolute and always in Premiere's spelling, `file://localhost/` and a percent-encoded path, a Windows drive as `C%3a`. No relative mode and no `--absolute-paths` flag: the file only opens on the machine and at the project location it was written for, and the method description says so. `premiereAssetUrl` is the one place that builds it; the percent-encoding is `encodePath` in `export/handoff.ts`, shared with `otioAssetUrl`.
5. **What is mapped.** Video and audio tracks, bottom first, in timeline order; a hidden video track and a muted audio track are `<enabled>FALSE</enabled>`; a muted video track keeps its picture and its sound is the disabled one. Media clips are `<clipitem>`s with a `<file>` (full definition at the first use in document order, `<file id/>` after; name, `pathurl`, rate, duration, and the picture size and audio channels and sample rate where ffprobe could read them, otherwise those blocks are left out, never invented). `speed` is a Time Remap filter in percent on the picture and on its sound. **Sound of video-track clips:** the same rule as ADR 0045 decision 5 (`mirrorsSound`: media clips whose asset is not a still image, decided by kind): one extra audio track per video track after all the real audio tracks, a linked audio `<clipitem>` for each such clip, same range and speed, disabled where the clip is muted. xmeml links natively, so picture and sound are tied with `<link>` elements (each lists both, itself included, with `mediatype`, `trackindex` and `clipindex`), where OTIO could only use metadata. **Dissolves:** where `edgeTransitions` says a clip has mode `dissolve`, a `<transitionitem>` Cross Dissolve (`alignment` center, `start` and `end` = the cut minus and plus the effective half length in frames) sits between the two `<clipitem>`s; the mirrored sound gets a Cross Fade (+3dB) between the two sound clips when both have sound. A shaped dissolve (wipe, push, iris) is written as the plain one with a warning. Generated and nested timeline clips keep their slot: a `<clipitem>` of their timeline length with an offline `<file>` (a name, no `pathurl`) and the missing-media warning of ADR 0045 decision 6; a nested clip of unknown length is skipped with a warning. Markers: `<marker>` with name and frame; the colour is not carried and is named in one warning when any marker has one.
6. **What is not exported, said in `warnings`** by the same `Dropped` and `leftOut` as OTIO (`export/handoff.ts`, one list and one wording): program tracks, subtitle tracks, dips and fades, transition shapes, transforms and keys, colour grades, film finish and effects, per-format clip overrides, audio effects, sound fades, clip gain (`audio.gain`) only where there is no sound to level (slice 2 writes it as an Audio Levels filter), `behind` tracks as plain tracks, the letterbox. The sound of video-track clips is not among them: it is carried.
7. **Where it is written.** `exports/<timeline>.xml` or `out`, which must end in `.xml` (refused with `InvalidOperation` otherwise, so a timeline or project file is never overwritten); atomic (`writeTextAtomic`). An image project is refused with `InvalidOperation`. Both refusals are `#handoffGuard` in `ExportService`, shared with `otio`, as is the probing of what the converter needs (`#handoffFacts`: handle lengths of dissolving tracks, nested lengths, and per asset the picture size and audio format; Premiere XML probes every media asset, OTIO only those of video tracks and dissolves).
8. **Surface.** Method `export.premiereXml` (params `timeline`, `out`, `view`; result `path`, `timeline`, `fps`, `tracks`, `clips`, `markers`, `warnings`), CLI `frameshell export premiere [--timeline id] [--out file.xml]` (prints the path and a `warning:` line each), MCP tool `export_premiere_xml` from the registry. The app menu (File > Export Premiere XML…) is slice 2, built. Protocol 181.
9. **Shared helper.** `packages/core/src/export/handoff.ts` holds what both writers share and nothing else: `Dropped`, `leftOut`, the notices of skipped tracks, `behind` tracks, the letterbox and clips of unknown length, the missing-media name and warning, `placeClip`, `baseName`, `sourceName`, `encodePath`. OTIO's output is byte-identical (golden `otio-edit.json` unchanged). The one difference between writers, what happens to `audio.gain`, is a parameter of `leftOut`. `mirrorsSound` and `soundMirrorName` stay in `otio.ts`, where ADR 0045 puts them; the xmeml writer imports `mirrorsSound`.

## Considered options

- **`dissolves` as hard cuts with one warning.** Smaller, but loses the one thing a Cross Dissolve gives an editor for free. Rejected by the owner's answer.
- **A relative `pathurl` or an `--absolute-paths` flag.** Premiere does not resolve a relative path against the file reliably; the owner chose always absolute.
- **FCP X (`fcpxml`) or CMX 3600 EDL.** Other formats with their own writers; not asked for.
- **An XML library.** A dependency for a document built as a tree of 20 element kinds; the structural test in this repo (`premiere-check.ts`) parses it back.
- **Audio Levels filter for `audio.gain`.** Left to a warning in slice 1 for not being verifiable here; written in slice 2 (below), marked unverified.

## Consequences and open points

- Not tested against Premiere Pro. The elements are modelled on the xmeml Final Cut 7 writes and Premiere reads (the dissolve's explicit positions and the Audio Levels filter are not shown to be Premiere's own spelling, see "Slice 2"), and details that only the real reader shows (the audio crossfade effect id, how a Time Remap filter reads `in` and `out`, a stereo file on one audio track item, an offline file with no `pathurl`) can need a correction after the owner's first import; the unit tests would then move with it.
- The sound of a video-track clip also exists in the imported media itself: Premiere links the picture to the file's own audio on import, so the person deletes one of the two (here the audio items are the linked ones, and are the only ones written).
- Track names are not carried (xmeml has none); the order is.
- Later: transforms and keys as Basic Motion keyframes.

## Slice 2 (built; #710)

The owner decided on 2026-11-19 (question Q1, every recommendation accepted):

1. **App menu, one path with OTIO.** File > Export Premiere XML… (en + es) sits after File > Export OpenTimelineIO…, a video project's only. Both are one hand-off path in the app: a `HandoffKind` (`otio` | `premiere`), one save dialog (`pickHandoffExport`: title, file filter and extension per kind), one IPC channel `timeline:export-handoff` (the kind and the timeline), one renderer effect and one notice (`handoffNotice`, which names the CLI command that lists what the file leaves out). Main asks where, the daemon writes (`export.otio` or `export.premiereXml`), the renderer never writes. The OTIO menu, dialog and notice read as before; the former `timeline:export-otio` channel is gone.
2. **Dissolves keep explicit positions.** A dissolve is a `<transitionitem>` centred on the cut (`start` = cut minus half, `end` = cut plus half) between two `<clipitem>`s that keep their own `start` and `end` and an `in`/`out` that is the source as the clip plays it, not widened by the half length. Decision 5 stands; the slice 1 wording that the shape follows what Premiere writes is corrected, because that is not shown. What is shown: Final Cut 7 writes `-1` for the `start` or `end` of a clip next to a transition (meaning "the cut point of that transition") and widens `in`/`out` by the half; the `fcp_xml` reader of `otio-fcp-adapter` 1.0.0 accepts both spellings (`-1` takes the transition's cut point, any other value is the position as given; centre alignment gives the cut as the middle of `start` and `end`), so explicit positions read as two butted clips with a dissolve of half a length each side. No evidence was found that Premiere itself writes `-1`. The `-1` form is not used: it needs the half lengths added back to `in`/`out`, and it is a change of decision 5 if the owner's first Premiere import asks for it.
3. **Reader test.** `packages/core/test/premiere-real.test.ts` (opt in, `FRAMESHELL_TEST_OTIO=1`, skipped otherwise) writes a timeline with a cut, a dissolve, a gap, speed 2, gain, a generated clip, a marker, a muted clip, a muted track and a hidden track and reads it with `opentimelineio` and `otio-fcp-adapter` (pinned `1.0.0`, next to `opentimelineio==0.18.1`, in the existing ubuntu shard 1 CI step): track kinds and durations, `Clip`, `Gap` and `Transition` (`SMPTE_Dissolve`, half length each side) sequences, source ranges, missing media for generated clips, markers, disabled flags, and that each sound clip links to its picture. The Python runner is shared with the OTIO test (`test/otio-python.ts`). It is a reader of the FCP7 format, not Premiere; it says the file is well-formed xmeml with the layout intended, not that Premiere accepts it. The adapter was checked against its source, not run on the machine that wrote this slice (no OpenTimelineIO wheel for its Python); the first CI run of the test passed against the real reader.
4. **`audio.gain` as an Audio Levels filter.** A clip's `audio.gain` (dB) is a `<filter>` on its audio `<clipitem>` (an audio-track clip and the sound mirror of a video-track clip; never on the picture): effect `Audio Levels` (`audiolevels`), one parameter `level`, `valuemin` 0, `valuemax` 3.98109, `value` linear 10^(dB/20) (0 dB = no filter). A gain above +12 dB is written as +12 dB (3.98109) with a warning; a clip whose asset has no sound to level (a still image) is named as "not exported" as before; a clip whose gain is keyed (`keys.gain`) writes none, the keys being named. The spelling is from FCP7 and Premiere files as remembered and is **unverified**: the first Premiere import decides whether it needs a correction. OTIO keeps gain as metadata with its warning (its golden is unchanged): `leftOut` takes the outcome as `string | undefined`, `undefined` meaning the file carries it.
5. **UNC paths.** A Windows UNC root `\\server\share\project` is written `file://localhost//server/share/project/...` (two slashes after `localhost`, the share's own). A test pins that spelling. It is **unverified** against Premiere.
6. **Leftovers of the slice 1 review.** The CLAUDE.md row names what is true; `PremiereXmlExport.tracks`/`clips`/`markers`, `PremiereAssetInfo.height` and `Dropped.warnings()` have TSDoc; the `EXPORT_USAGE` comment names both commands; the `clips` result description says clip items on the video and audio tracks, offline ones included, and leaves the sound-mirror items out; `#handoffGuard` returns the project config and `premiereXml` uses it for the size, one read of the project per export. No wire change: descriptions only, `PROTOCOL_VERSION` stays 181.

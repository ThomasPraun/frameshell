# OpenTimelineIO export: a derived file, export only, what is left out is said

#383 (epic #451) asks for OTIO and Premiere XML export so a cut made with an agent can go on in an editor. SPEC decision 3 already settles the direction: the declarative timeline JSON is the source of truth and OTIO is **export only**. This ADR records how the export is built; it changes no existing decision. The owner chose the options below on 2026-11-18 (question Q1, every recommendation accepted). **Slice 1 is built: cuts, gaps, speed, mute and hide, markers. Slice 2 is built: dissolves as `Transition.1`, File > Export OpenTimelineIO… in the app, image projects refused, and the opt-in real-library test. Premiere XML is a later slice (#701); #383 stays open.** The owner answered the slice 2 questions on 2026-11-19 (Q1); they are in decisions 5, 7 and 9.

## Context (verified)

- Timelines are JSON files with video, audio, program and subtitle tracks, first video track = bottom layer; a media clip lasts `(out - in) / speed` on the timeline (`clipLength` in `packages/schema/src/transitions.ts`), a generated or nested clip lasts `duration` (a nested one without it: the rest of the nested timeline).
- Times are stored in seconds and snapped by the core to the project's frame grid (`FrameGrid`, 3 decimals); the project `fps` is a positive number and may be fractional (30000/1001).
- A derived file that is written next to the project and never read back already exists: `cover` writes `exports/<timeline>-cover.png`.

## Decision

1. **Export only, read-only.** `export.otio` writes a file derived from the timeline and never changes it (no transaction, no journal entry, not a `mutating` method, no review-mode proposal). The file is regenerated on every call and never read back: no import, no sync, nothing in the project depends on it (SPEC decision 3).
2. **Format.** Plain OTIO JSON as OpenTimelineIO 0.15 and later writes it: `Timeline.1` (`name` = timeline id, `global_start_time` 0, `metadata.frameshell` = `timelineId`, `revision`, `schemaVersion`), one `Stack.1` of `Track.1` children with markers as `Marker.2` on the stack, `Clip.2`, `Gap.1`, `ExternalReference.1`, `MissingReference.1`, `LinearTimeWarp.1`, `Transition.1`, `RationalTime.1`, `TimeRange.1`. A `Clip.2` keeps its reference in `media_references` under `DEFAULT_MEDIA` with `active_media_reference_key`, which is how OTIO 0.15+ stores it (`media_reference` is `Clip.1`). No new dependency, no Python, no render, no job queue: a pure converter (`packages/core/src/export/otio.ts`).
3. **Time.** The rate of every time is the project fps, passed unchanged when it is fractional. Every value is one `RationalTime.1` whose `value` is a whole frame count, `Math.round(seconds * fps)`; a gap is the difference of two frame positions, never a sum of rounded lengths, so nothing drifts over a long track. Clip length is `clipLength` with the engine's `TransitionContext` (`sourceDuration` of a nested clip comes from `TimelineService.nestedDuration`); it is never recomputed privately.
4. **Paths.** `target_url` is relative to the `.otio` file, `/`-separated and percent-encoded, so the project folder can move; `--absolute-paths` writes `file://` URLs. An asset with no relative path from the file (another Windows drive) gets a `file://` URL. `otioAssetUrl` is the one place that builds it.
5. **What is mapped (slices 1 and 2).** Video and audio tracks in timeline order (OTIO bottom track first = Frameshell first video track). A hidden video track and a muted audio track get `enabled: false`; a muted video track keeps its picture, so it stays enabled with a warning (OTIO has no switch for its sound alone). A clip muted on an audio track is disabled. Media clips: `Clip.2` named after the file, `source_range` starting at the source `in` and lasting the clip's **timeline** length, an `ExternalReference.1`, `LinearTimeWarp.1` with `time_scalar` = `speed` when it is not 1 (OTIO lays items out one after another by `source_range.duration` and effects play no part in that layout; the time warp only says how much media the duration consumes, so a 2 s clip at speed 2 is 2 s long in the file and reads 4 s of source from `in`, as the CMX 3600 adapter computes it), and `metadata.frameshell` with `clipId`, `start`, `length` (timeline seconds), `gain` and `speed` when set. Holes become `Gap.1`, sized from frame positions (a clip ends at `Math.round((start + length) * fps)`). **Dissolves (slice 2):** where `edgeTransitions` (`packages/schema/src/transitions.ts`, never recomputed here, with the same `TransitionContext` as `clipLength`) says a clip has mode `dissolve` (it starts where the clip before it ends and the two share the handle), a `Transition.1` named `""` of type `SMPTE_Dissolve` sits between the two `Clip.2`, `in_offset` and `out_offset` both `Math.round(half * fps)` frames (centred on the cut, as OTIO draws it), `metadata.frameshell` with `clipId`, `dissolve` and `half` seconds. A transition has no length of its own, so the neighbours' lengths, the gaps and the track length are those of slice 1; a `Transition.1` is always between two `Clip.2`, never next to a `Gap.1` (it is only written when the frame positions of the two clips meet). The half length is the effective one (cut to the handle both files have), so a media file's duration is probed for tracks that have a dissolve; a file that cannot be probed has no handle, so its dissolve plays as a dip, as in a render. A generated or nested clip is eligible too (`clipHandles`). A **shaped** dissolve (`shape`: wipe, push, iris, ADR 0030) is written as the same plain `SMPTE_Dissolve`, its shape only in `metadata.frameshell.shape`, with a warning. Markers: `Marker.2` with `name` = label, a zero-length `marked_range`, colour red, orange, yellow, green, blue or purple as OTIO `RED`… `PURPLE`, `GREEN` when unset, sorted by time.
6. **Generated and nested timeline clips keep their slot** (`hyperframes`, `remotion`, `blender`, any adapter): a `Clip.2` with a `MissingReference.1`, named `<type> <source name>` (`timeline <name>` for a nested one), `source_range` from 0 for the clip's timeline length, `metadata.frameshell.type`, plus a warning telling the person to render it and relink the file. A nested clip whose length is unknown is skipped with a warning.
7. **What is not exported, said in `warnings`** (one line per kind, with the first five clip ids): multicam program tracks and their shots, subtitle tracks, **dips and fades** (`fadeIn`, `fadeOut`, and a `dissolve` with no handle or no clip ending where it starts, which plays as a dip or a fade in and has no OTIO item), **transition shapes** (named whether or not a dissolve carries them; a `shape` with no `dissolve` is inert and said so), transforms and keys, colour grades, film finish and effects (`vignette`, `grain`, `backdrop`, `motionBlur`), audio effects, the muted sound of a video clip, **the sound of media clips on a video track** (a video-track clip is written on a `Video` track only and OTIO keeps sound on `Audio` tracks, so a talking head on V1 exports without its sound; one warning when the clip and its track are not muted, the owner kept it a warning on 2026-11-19; mirroring it onto generated `Audio` tracks is a later slice, OT3), per-format clip overrides (`formats`), transition `shape`, and a track that sits `behind` the person (subject matte, ADR 0032: exported as a plain track). Clip `gain` is kept only as metadata. The timeline `letterbox` is named in a warning too; the primary format is exported.
8. **Where it is written.** `exports/<timeline>.otio` by default, or `out`, which must end in `.otio` (refused otherwise with `InvalidOperation`, so a timeline or project file can never be overwritten); the folder is created and the file written atomically (`writeTextAtomic`). The result carries `path`, `timeline`, `fps`, `tracks`, `clips`, `markers` and `warnings`.
9. **Surface.** Method `export.otio` (params `timeline`, `out`, `absolutePaths`, `view`), CLI `frameshell export otio [--timeline id] [--out file.otio] [--absolute-paths]` (prints the path and a `warning:` line each), MCP tool `export_otio` from the registry. **Image projects are refused** with `InvalidOperation` ("image projects have no cut to hand to an editor"): they are stills as layers (ADR 0017), and an OTIO of them means nothing; the daemon is the guard. App (slice 2): File > Export OpenTimelineIO… (`export-otio`, command `exportOtio`, no accelerator) asks where in a save dialog (default `exports/<timeline>.otio`, filter `.otio`), the daemon's `export.otio` writes the file (the renderer and main never write it; a folder outside the project is fine, `target_url`s stay relative to the folder picked, or `file://` where there is no relative path), and a notice in the status bar names the file and counts what it leaves out. The item is disabled in image windows (`VIDEO_MENU_ITEMS`). `target_url` stays a percent-encoded relative path (owner, 2026-11-19). The wire does not change: slice 2 adds a refusal and a longer description, so the protocol stays at 180.

## Considered options

- **Generated and nested clips as `Gap.1`:** keeps the file smaller but the editor loses the slot, the name and the knowledge that something belongs there. Rejected for a missing reference of the clip's length.
- **Render generated clips into the export:** needs the clip render queue, Chrome and time; an export that waits on renders is not a quick hand-off. Later, if asked.
- **The `opentimelineio` Python package or a native binding:** a dependency for a file that is a JSON tree; the structural test in this repo checks the shape, and an opt-in test (`FRAMESHELL_TEST_OTIO=1`) reads the file with the real library.
- **OTIO import:** a second source of truth, against SPEC decision 3.
- **`media_reference` (`Clip.1`):** older readers; OTIO 0.15 reads `Clip.2` and has done so since 2021.

## Consequences and open points

- OTIO's layout is sequential: an item takes the length of its `source_range.duration`, whatever its effects. The first draft wrote the source length for a clip with `speed` other than 1, which made every later item on the track, the track and the timeline the wrong length in any OTIO reader; review changed it to the timeline length (the owner's decision said only "speed (LinearTimeWarp)"). The source an editor reads for such a clip is `in` plus its length times `time_scalar`.
- The sound of a media clip on a video track is not in the file, only named in `warnings`; mirroring it onto `Audio` tracks is the owner's call.
- The file is checked structurally in the unit tests (every object has its `OTIO_SCHEMA`, every time is a whole-frame `RationalTime.1`, a `Transition.1` has whole-frame offsets and a `Clip.2` on both sides, a golden document); `packages/core/test/otio-real.test.ts` reads it with the real library and is the only test that does: `pip install opentimelineio`, then `FRAMESHELL_TEST_OTIO=1 pnpm test packages/core/test/otio` (`FRAMESHELL_TEST_PYTHON` names the interpreter). Without the variable it is skipped, with it a missing library is a failure.
- A `Transition.1` overlaps the clips' own ranges in OTIO's model (`in_offset` of the clip before, `out_offset` of the clip after), where Frameshell plays a dissolve into the handles outside the clips' ranges. The cut point and every clip length are the same in both; an editor reading the file shows the dissolve centred on the cut and may ask for handles.
- Later slices: mirroring the sound of video-track clips onto `Audio` tracks (OT3), Premiere XML (#701).

# OpenTimelineIO export: a derived file, export only, what is left out is said

#383 (epic #451) asks for OTIO and Premiere XML export so a cut made with an agent can go on in an editor. SPEC decision 3 already settles the direction: the declarative timeline JSON is the source of truth and OTIO is **export only**. This ADR records how the export is built; it changes no existing decision. The owner chose the options below on 2026-11-18 (question Q1, every recommendation accepted). **Slice 1 is built: cuts, gaps, speed, mute and hide, markers. Slice 2 is built: dissolves as `Transition.1`, File > Export OpenTimelineIO… in the app, image projects refused, and the opt-in real-library test. Slice 3 is built: the sound of video-track media clips mirrored on `Audio` tracks, gain and sound fades named in warnings. Premiere XML is its own export, ADR 0047 (#701); #383 closes with it.** The owner answered the slice 2 questions on 2026-11-19 (Q1); they are in decisions 5, 7 and 9. The slice 3 answers of the same day (every recommendation accepted) are in decisions 5 and 7: the mirror goes by asset kind only (never a probe for an audio stream), one mirror track per video track, a muted clip written as a disabled slot, gain stays metadata with one warning.

## Context (verified)

- Timelines are JSON files with video, audio, program and subtitle tracks, first video track = bottom layer; a media clip lasts `(out - in) / speed` on the timeline (`clipLength` in `packages/schema/src/transitions.ts`), a generated or nested clip lasts `duration` (a nested one without it: the rest of the nested timeline).
- Times are stored in seconds and snapped by the core to the project's frame grid (`FrameGrid`, 3 decimals); the project `fps` is a positive number and may be fractional (30000/1001).
- A derived file that is written next to the project and never read back already exists: `cover` writes `exports/<timeline>-cover.png`.

## Decision

1. **Export only, read-only.** `export.otio` writes a file derived from the timeline and never changes it (no transaction, no journal entry, not a `mutating` method, no review-mode proposal). The file is regenerated on every call and never read back: no import, no sync, nothing in the project depends on it (SPEC decision 3).
2. **Format.** Plain OTIO JSON as OpenTimelineIO 0.15 and later writes it: `Timeline.1` (`name` = timeline id, `global_start_time` 0, `metadata.frameshell` = `timelineId`, `revision`, `schemaVersion`), one `Stack.1` of `Track.1` children with markers as `Marker.2` on the stack, `Clip.2`, `Gap.1`, `ExternalReference.1`, `MissingReference.1`, `LinearTimeWarp.1`, `Transition.1`, `RationalTime.1`, `TimeRange.1`. A `Clip.2` keeps its reference in `media_references` under `DEFAULT_MEDIA` with `active_media_reference_key`, which is how OTIO 0.15+ stores it (`media_reference` is `Clip.1`). No new dependency, no Python, no render, no job queue: a pure converter (`packages/core/src/export/otio.ts`).
3. **Time.** The rate of every time is the project fps, passed unchanged when it is fractional. Every value is one `RationalTime.1` whose `value` is a whole frame count, `Math.round(seconds * fps)`; a gap is the difference of two frame positions, never a sum of rounded lengths, so nothing drifts over a long track. Clip length is `clipLength` with the engine's `TransitionContext` (`sourceDuration` of a nested clip comes from `TimelineService.nestedDuration`); it is never recomputed privately.
4. **Paths.** `target_url` is relative to the `.otio` file, `/`-separated and percent-encoded, so the project folder can move; `--absolute-paths` writes `file://` URLs. An asset with no relative path from the file (another Windows drive) gets a `file://` URL. `otioAssetUrl` is the one place that builds it.
5. **What is mapped (slices 1 to 3).** Video and audio tracks in timeline order (OTIO bottom track first = Frameshell first video track). A hidden video track and a muted audio track get `enabled: false`; a muted video track keeps its picture, so it stays enabled (its sound is on the mirror track, which is the disabled one). A clip muted on an audio track is disabled. **Sound mirror (slice 3):** OTIO keeps sound on `Audio` tracks, so for every video track that has a media clip with sound (decided by the asset's kind: a video or audio file yes, a still image never; the file is not probed for an audio stream, and a file that cannot be read is taken to have sound) one extra `Audio` track is written after every real track, so the ordinals of the real audio tracks (`A1`…`An`) do not change. It is named `<video track name> sound`, carries `metadata.frameshell.mirrorOf` = the video track id (and `muted` when that track is), and holds the same `Clip.2` of each such clip: same name, `source_range`, `ExternalReference.1`, `LinearTimeWarp.1` for `speed`, `Gap.1` where the picture track has a hole or a clip without sound (a generated or nested clip, a still), the same `Transition.1` where the picture has a dissolve between two clips that both have sound, and `metadata.frameshell` with the picture's `clipId`, `start`, `length`, `gain` and `speed`, plus `linkedClipId` (= `clipId`) and `sound: true`, which is the only link between the picture and its sound (OTIO has no link object). A muted clip (`audio.muted`) stays in the mirror as a disabled slot (`enabled: false`) and its picture stays enabled; a muted video track disables the mirror track; a hidden video track still plays its sound, so its mirror is enabled. `tracks` counts the mirror tracks, `clips` only the clips of the timeline's own tracks. `trackObject` writes both kinds of track from one layout code with a mode; `mirrorsSound` and `soundMirrorName` in `export/otio.ts` are the one place that says which clips mirror and how the track is named (the Premiere XML writer, #701, reads the same). Media clips: `Clip.2` named after the file, `source_range` starting at the source `in` and lasting the clip's **timeline** length, an `ExternalReference.1`, `LinearTimeWarp.1` with `time_scalar` = `speed` when it is not 1 (OTIO lays items out one after another by `source_range.duration` and effects play no part in that layout; the time warp only says how much media the duration consumes, so a 2 s clip at speed 2 is 2 s long in the file and reads 4 s of source from `in`, as the CMX 3600 adapter computes it), and `metadata.frameshell` with `clipId`, `start`, `length` (timeline seconds), `gain` and `speed` when set. Holes become `Gap.1`, sized from frame positions (a clip ends at `Math.round((start + length) * fps)`). **Dissolves (slice 2):** where `edgeTransitions` (`packages/schema/src/transitions.ts`, never recomputed here, with the same `TransitionContext` as `clipLength`) says a clip has mode `dissolve` (it starts where the clip before it ends and the two share the handle), a `Transition.1` named `""` of type `SMPTE_Dissolve` sits between the two `Clip.2`, `in_offset` and `out_offset` both `Math.round(half * fps)` frames (centred on the cut, as OTIO draws it), `metadata.frameshell` with `clipId`, `dissolve` and `half` seconds. A transition has no length of its own, so the neighbours' lengths, the gaps and the track length are those of slice 1; a `Transition.1` is always between two `Clip.2`, never next to a `Gap.1` (it is only written when the frame positions of the two clips meet). The half length is the effective one (cut to the handle both files have), so a media file's duration is probed for tracks that have a dissolve; a file that cannot be probed has no handle, so its dissolve plays as a dip, as in a render. A generated or nested clip is eligible too (`clipHandles`). A **shaped** dissolve (`shape`: wipe, push, iris, ADR 0030) is written as the same plain `SMPTE_Dissolve`, its shape only in `metadata.frameshell.shape`, with a warning. Markers: `Marker.2` with `name` = label, a zero-length `marked_range`, colour red, orange, yellow, green, blue or purple as OTIO `RED`… `PURPLE`, `GREEN` when unset, sorted by time.
6. **Generated and nested timeline clips keep their slot** (`hyperframes`, `remotion`, `blender`, any adapter): a `Clip.2` with a `MissingReference.1`, named `<type> <source name>` (`timeline <name>` for a nested one), `source_range` from 0 for the clip's timeline length, `metadata.frameshell.type`, plus a warning telling the person to render it and relink the file. A nested clip whose length is unknown is skipped with a warning.
7. **What is not exported, said in `warnings`** (one line per kind, with the first five clip ids): multicam program tracks and their shots, subtitle tracks, **dips and fades** (`fadeIn`, `fadeOut`, and a `dissolve` with no handle or no clip ending where it starts, which plays as a dip or a fade in and has no OTIO item), **transition shapes** (named whether or not a dissolve carries them; a `shape` with no `dissolve` is inert and said so), transforms and keys, colour grades, film finish and effects (`vignette`, `grain`, `backdrop`, `motionBlur`), audio effects, **sound fades** (`audio.fadeInMs`, `audio.fadeOutMs`, on audio-track and video-track clips alike), per-format clip overrides (`formats`), and a track that sits `behind` the person (subject matte, ADR 0032: exported as a plain track). Clip `gain` (`audio.gain`, in dB) is kept only as `metadata.frameshell.gain`, on audio-track clips and on mirror clips, with **one aggregated warning** ("kept as metadata only, with no level change in the file") for every clip whose own sound is not muted (`audio.muted`; a clip on a muted track still counts) and has a gain other than 0, so no editor plays a level the file does not carry without the person knowing. The timeline `letterbox` is named in a warning too; the primary format is exported.
8. **Where it is written.** `exports/<timeline>.otio` by default, or `out`, which must end in `.otio` (refused otherwise with `InvalidOperation`, so a timeline or project file can never be overwritten); the folder is created and the file written atomically (`writeTextAtomic`). The result carries `path`, `timeline`, `fps`, `tracks`, `clips`, `markers` and `warnings`.
9. **Surface.** Method `export.otio` (params `timeline`, `out`, `absolutePaths`, `view`), CLI `frameshell export otio [--timeline id] [--out file.otio] [--absolute-paths]` (prints the path and a `warning:` line each), MCP tool `export_otio` from the registry. **Image projects are refused** with `InvalidOperation` ("image projects have no cut to hand to an editor"): they are stills as layers (ADR 0017), and an OTIO of them means nothing; the daemon is the guard. App (slice 2): File > Export OpenTimelineIO… (`export-otio`, command `exportOtio`, no accelerator) asks where in a save dialog (default `exports/<timeline>.otio`, filter `.otio`), the daemon's `export.otio` writes the file (the renderer and main never write it; a folder outside the project is fine, `target_url`s stay relative to the folder picked, or `file://` where there is no relative path), and a notice in the status bar names the file and counts what it leaves out. The item is disabled in image windows (`VIDEO_MENU_ITEMS`). `target_url` stays a percent-encoded relative path (owner, 2026-11-19). The notice names the way to list what the file leaves out, `frameshell export otio --out <file>.otio` in a terminal (slice 3; the app behaves as before). The wire does not change: slice 2 added a refusal and a longer description and slice 3 only description and warning texts (the result's fields and what `tracks` and `clips` count are the same kinds of number), so the protocol stays at 180.

## Considered options

- **Generated and nested clips as `Gap.1`:** keeps the file smaller but the editor loses the slot, the name and the knowledge that something belongs there. Rejected for a missing reference of the clip's length.
- **Render generated clips into the export:** needs the clip render queue, Chrome and time; an export that waits on renders is not a quick hand-off. Later, if asked.
- **The `opentimelineio` Python package or a native binding:** a dependency for a file that is a JSON tree; the structural test in this repo checks the shape, and an opt-in test (`FRAMESHELL_TEST_OTIO=1`) reads the file with the real library.
- **OTIO import:** a second source of truth, against SPEC decision 3.
- **`media_reference` (`Clip.1`):** older readers; OTIO 0.15 reads `Clip.2` and has done so since 2021.

## Consequences and open points

- OTIO's layout is sequential: an item takes the length of its `source_range.duration`, whatever its effects. The first draft wrote the source length for a clip with `speed` other than 1, which made every later item on the track, the track and the timeline the wrong length in any OTIO reader; review changed it to the timeline length (the owner's decision said only "speed (LinearTimeWarp)"). The source an editor reads for such a clip is `in` plus its length times `time_scalar`.
- The sound of a video-track clip lives twice if an editor also links the file's own audio to the picture: once on the mirror track and once as the linked audio of the imported clip. A reader sees the picture and its sound as two tracks tied only by the `clipId` metadata; OTIO has no link object, and an editor that wants the pair to move together has to be told. Mute one of the two there.
- The mirror is decided by kind, never by probing for an audio stream, so a silent video file (a screen recording with no audio track) or an animated GIF still gets a mirror clip; it plays nothing. "Not a still image" is read from the `still` flag of the same ffprobe the dissolve handles use (cached by size and mtime; no helper classifies images by extension), so every media asset of a video track is probed once and an OTIO export always needs ffprobe. Cheaper than a probe per file and never wrong the other way (a clip with sound with no mirror).
- The file is checked structurally in the unit tests (every object has its `OTIO_SCHEMA`, every time is a whole-frame `RationalTime.1`, a `Transition.1` has whole-frame offsets and a `Clip.2` on both sides, a golden document); `packages/core/test/otio-real.test.ts` reads it with the real library and is the only test that does: `pip install opentimelineio`, then `FRAMESHELL_TEST_OTIO=1 pnpm test packages/core/test/otio` (`FRAMESHELL_TEST_PYTHON` names the interpreter). Without the variable it is skipped, with it a missing library is a failure. CI runs it in a step of its own on ubuntu only (Python 3.12, `opentimelineio==0.18.1`, the version it was run against), and only when `scripts/test-scope.mjs` selects OTIO tests. It reads the mirror tracks too (kind, enabled, durations, `Transition`, clip ids).
- A `Transition.1` overlaps the clips' own ranges in OTIO's model (`in_offset` of the clip before, `out_offset` of the clip after), where Frameshell plays a dissolve into the handles outside the clips' ranges. The cut point and every clip length are the same in both; an editor reading the file shows the dissolve centred on the cut and may ask for handles.
- Later slices: Premiere XML is built as its own writer in ADR 0047 (#701), sharing `export/handoff.ts` with this converter.

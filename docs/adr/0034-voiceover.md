# Voiceover from text: a speech provider contract and a provider-agnostic pipeline in core

Films made from a brief often want narration (#470, epic #451). SPEC decision 10 said text-to-speech was an asset the agent produces with its own tools. This ADR takes speech generation into Frameshell through our own provider contract, as #478 chose (our contract, not HyperFrames' `tts`), with the deterministic work in core and no voice shipped. Decided by the owner on 2026-11-10 (option D of the proposal on #470, all recommendations accepted); it changes SPEC decision 10 and adds decision 31.

## Context (verified)

- Transcription already has the shape: `TranscriptionProvider` in `packages/plugin-api/src/index.ts`, registered by plugins through `contributes.transcriptionProviders`, looked up by `PluginHost.transcriptionProvider` (`packages/core/src/plugins/host.ts`) only in trusted projects.
- The manifest's `contributes` is a strict object (`packages/schema/src/plugin.ts`): a key a host does not know fails the plugin's load there.
- Shoot scripts (ADR 0023) already read a script line by line, with speakers and `[LABEL: …]` cues (`parseShootScript`, `packages/schema/src/script.ts`). Numbers are said through one function, `spellNumber` (`packages/schema/src/numbers.ts`).
- Silence and pause detection exists for cut snapping (`energyEnvelope`, `energyProfile`, `snapToPause` in `packages/core/src/media/energy.ts`, ADR 0003), tuned for recordings: the quiet threshold is a percentile of the material.
- Mutating daemon methods get replay protection from `params.idempotencyKey` (`IdempotencyCache`, `packages/core/src/idempotency.ts`).
- No secret storage exists anywhere in the tree. Kokoro-82M weights are Apache-2.0, but its Spanish G2P goes through eSpeak NG, which is GPL-3.0 (bundled in `phonemizer`, a kokoro-js dependency).
- #470's numbers: about 2.2 to 3 words/s; a two-layer script (spoken form with respellings and numbers spelled out, display form for captions); cache per line by hash of voice, speed and text; trim head and tail silence with small padding; split takes at silences (5 ms RMS, -38 dB relative to peak, 60 ms minimum, 20 ms lead, 30 ms tail, 12 ms fades); round-trip each line through speech-to-text to catch misreads.

## Decision

1. **Voiceover is in scope.** SPEC decision 10 changes: transcription and speech generation are both provider interfaces; video, image and music stay assets the agent produces. Core owns the deterministic pipeline (script parsing, per-line cache, trim, silence split, the misread round trip, phrase clips the human corrects). Frameshell ships no voice in v1.
2. **`SpeechProvider` in the plugin API**, the transcription contract turned around: `id`, optional `version` (part of the cache key), optional `defaultVoice`, `voices()`, optional `estimate(text, voice, options)` → `{ cost, currency, characters? }`, and `synthesize(text, voice, options, context)` → `{ file, model?, notes? }`, a mono 16-bit PCM WAV under `context.outDir`. `context` carries `outDir`, `signal`, `ensureBinary` and `progress`. Plugins register it with `registerSpeechProvider` and declare it in `contributes.speechProviders`. The addition is additive, so `PLUGIN_API_VERSION` stays `"1"`; a manifest that declares `speechProviders` fails to load on hosts before this ADR (strict manifest), which plugin authors must know.
3. **One host lookup for both provider kinds.** `PluginHost` finds transcription and speech providers through one private lookup (trust, declared-but-broken plugin, not-found error with the loaded ids); each kind only names its maps, its manifest list, its error code and its install hint.
4. **Built-in providers come before plugin ones** and need no trust. Slice 1 has one, the **stand-in** (`FRAMESHELL_SPEECH_STAND_IN=1` in `frameshelld`, tests only): free, deterministic, one sine tone per word with silence around, so length follows word count and trimming has work to do.
5. **First real provider: a machine-level `command` provider** (slice 2): a TTS program the person installed, named in `configDir` only. One declared at project level (`frameshell.json`) is refused, so a downloaded project can never make Frameshell run a command, the same reason binary overrides are trust-sensitive.
6. **Cloud providers** come later as plugins, with the person's key from an **environment variable only** in v1 (works for CLI, daemon and app alike); the OS keychain later. Keys never reach project files, journal entries, progress messages or error data.
7. **Voiceover script = a script in `scripts/` with `voiceover: true`**, read with the shoot-script line rules (`parseVoiceoverScript` shares `parseShootScript`'s scene and line reading: one line per non-blank text line, `**Name:**`, `[LABEL: …]` cues never read). Frontmatter adds `language`, `provider`, `voice`. Each line has two forms joined by position: `display` (as written, digits kept, for captions) and `spoken` (what the voice reads). They differ by respellings `{display|spoken}` and by numbers with digits spelled out in `language` (`es`, `en`) through `spellNumbersIn`, which wraps `spellNumber`: one number speller, no twin. Heading timings `(0:00–0:09)` work as in shoot scripts and stay out of anchors. A scene whose words need longer than its timing at 2.5 words/s (`VOICEOVER_WORDS_PER_SECOND`) warns: trim the text, never stretch the picture. Line ids are `<scene slug>-<n>`, n counting the scene's spoken lines only, so a cue-only line never shifts them.
8. **Generated takes are project media** in `assets/voiceover/<script slug>/<line id>.wav` (script slug as for shoot files, `shootSlug`), never in `.frameshell/cache`: a paid take is not regenerable for free. `gc` never touches `assets/`.
9. **The cache key travels inside the take.** Each take's WAV holds a RIFF chunk `fsvo` with its key (SHA-256 of key version, provider id and version, voice, options, spoken text) and what made it. A line whose file holds its key is `cached`; a key found in another file of the folder (a line that moved) is `copied`; otherwise it is `generated`. No index file to lose with `.frameshell/`, and a cloned project keeps its cache. A `.wav` there without the chunk (made or edited by hand) is the person's: the call refuses before generating anything, and never overwrites it. `TAKE_KEY_VERSION` bumps when what a key stands for changes.
10. **Trim head and tail silence** on the 10 ms energy envelope of ADR 0003, with its own named threshold: quiet = 38 dB below the take's loudest 10 ms (#470), kept 20 ms before the first sound and 30 ms after the last. A synthetic voice has no room noise, so a peak reference is steadier than ADR 0003's percentile threshold, which stays as it is. A take quieter than -60 dBFS throughout is kept whole with a warning. The 5 ms RMS and fades of #470 belong to the silence split (slice 3).
11. **`voiceover.generate { cwd, script, lines?, provider?, voice?, yes }`** is one mutating daemon method that waits for its result and reports progress as `progress` notifications (not a queue job: the cost refusal and the per-line states must reach the caller). Order: parse, refuse a script without `voiceover: true`, pick lines, resolve provider and voice (unknown ones name the valid ids), plan cache states, refuse foreign files, estimate the cost, generate line by line, write each take atomically, then import every written take with one `asset.import` call. Calls are serialized per project. A provider failure stops the run: the takes finished before it stay written and imported (they may have been paid for) and the error `SpeechFailed` lists them; the next call reuses them.
12. **Paid generation needs an explicit confirm**, also when an agent calls it. A provider whose estimate for the lines to generate is above 0 makes the call fail with `ConfirmationRequired`, carrying the cost, characters and lines, until it is called with `yes` (CLI `--yes`, a dialog in the app later). Cached and copied lines cost nothing and need no confirm. The method is `mutating`, so a retried RPC with the same `idempotencyKey` returns the first result and never charges twice. The skill tells agents never to pass `yes` without the person's confirmation.
13. **Misread check.** Slice 3 round-trips each take through the project's transcription provider and compares it with the line (`alignWords`/`compareTake` normalization). It needs the trusted whisper-cpp plugin; untrusted projects get generation without verification, and the result says so.
14. **Kokoro** stays the local candidate, behind a spike after the pipeline ships (ORT Web speed, Spanish quality). If it goes ahead, its G2P is our own TypeScript (rule-based Spanish, dictionary English): no GPL anywhere (no eSpeak NG, no `phonemizer`).
15. **Preview pitch** at clip speed other than 1 (the preview resamples, export uses `atempo`; #499) blocks only per-phrase tempo, not the first slices. Placement of phrases on markers and beats waits for the TimeRef contract of ADR 0029.
16. **Slices.** (1) contract and pipeline, no real voice: this ADR's points 2 to 4 and 7 to 12, CLI `frameshell voiceover generate <script> [--lines] [--provider] [--voice] [--yes]`, the MCP tool from the registry, the skill; (2) the `command` provider; (3) silence split and misread round trip; (4) placement on markers and the app UI; later cloud plugins and the Kokoro spike.

## Considered options

- **A. Keep decision 10, voiceover skill-only.** Rejected: every agent reinvents caching, trimming and the misread check, nothing works without an agent, and a paid generation never shows its cost first.
- **B. Contract and pipeline, first provider a plugin.** Taken in part: D is B plus a built-in machine-level provider, so voiceover works in untrusted projects without shipping a voice.
- **C. Kokoro built into core** on ONNX Runtime Web (like ADR 0022). Deferred: Spanish needs eSpeak NG (GPL-3.0); our own G2P has unproven quality. A spike comes after the pipeline.
- **A hash-to-file index in `.frameshell/`.** Rejected for the in-file mark: the index is lost with `.frameshell/` (not shared, not precious) and a fresh clone would pay again for every take.
- **Takes in `.frameshell/cache`.** Rejected: the cache must be regenerable for free; a paid take is not.
- **A queued job** (`job.list`) for generation. Rejected for slice 1: the cost refusal and the per-line result must reach the caller; progress notifications already cover long runs.

## Consequences

- SPEC: decision 10 changed, decision 31 added; §5.1 layout, §5.5 scripts, §7 CLI, §8.1 manifest, §8.2 extension points, §12 roadmap.
- Protocol: `voiceover.generate`, error codes `SpeechProviderNotFound`, `SpeechFailed`, `ConfirmationRequired`, `contributes.speechProviders` in `plugin.list`; `PROTOCOL_VERSION` bump.
- Schema: `contributes.speechProviders` (JSON Schema regenerated), `voiceover` added to the built-in command groups a plugin may not shadow, `parseVoiceoverScript` and `spellNumbersIn`.
- The speech provider sees only the spoken text and the options; it never sees project files, so a cloud plugin can send nothing else.
- The take mark makes `assets/voiceover/` safe to regenerate over: only files this pipeline wrote, unchanged, are ever replaced.

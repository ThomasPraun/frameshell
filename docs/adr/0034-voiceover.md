# Voiceover from text: a speech provider contract and a provider-agnostic pipeline in core

Films made from a brief often want narration (#470, epic #451). SPEC decision 10 said text-to-speech was an asset the agent produces with its own tools. This ADR takes speech generation into Frameshell through our own provider contract, as #478 chose (our contract, not HyperFrames' `tts`), with the deterministic work in core and no voice shipped. Decided by the owner on 2026-11-10 (option D of the proposal on #470, all recommendations accepted); it changes SPEC decision 10 and adds decision 39.

## Context (verified)

- Transcription already has the shape: `TranscriptionProvider` in `packages/plugin-api/src/index.ts`, registered by plugins through `contributes.transcriptionProviders`, looked up by `PluginHost.transcriptionProvider` (`packages/core/src/plugins/host.ts`) only in trusted projects.
- The manifest's `contributes` is a strict object (`packages/schema/src/plugin.ts`): a key a host does not know fails the plugin's load there.
- Shoot scripts (ADR 0023) already read a script line by line, with speakers and `[LABEL: …]` cues (`parseShootScript`, `packages/schema/src/script.ts`). Numbers are said through one function, `spellNumber` (`packages/schema/src/numbers.ts`).
- Silence and pause detection exists for cut snapping (`energyEnvelope`, `energyProfile`, `snapToPause` in `packages/core/src/media/energy.ts`, ADR 0003), tuned for recordings: the quiet threshold is a percentile of the material.
- Mutating daemon methods get replay protection from `params.idempotencyKey` (`IdempotencyCache`, `packages/core/src/idempotency.ts`).
- No secret storage exists anywhere in the tree. Kokoro-82M weights are Apache-2.0, but its Spanish G2P goes through eSpeak NG, which is GPL-3.0 (bundled in `phonemizer`, a kokoro-js dependency).
- #470's numbers: about 2.2 to 3 words/s; a two-layer script (spoken form with respellings and numbers spelled out, display form for captions); cache per line by hash of voice, speed and text; trim head and tail silence with small padding; split takes at silences (5 ms RMS, -38 dB relative to peak, 60 ms minimum, 20 ms lead, 30 ms tail, 12 ms fades); round-trip each line through speech-to-text to catch misreads.

## Decision

1. **Voiceover is in scope.** SPEC decision 10 changes: transcription and speech generation are both provider interfaces; video, image and music stay assets the agent produces. Core owns the deterministic pipeline (script parsing, per-line cache, trim, silence split, the misread round trip, phrase clips the human corrects). Frameshell ships no voice in v1.
2. **`SpeechProvider` in the plugin API**, the transcription contract turned around: `id`, optional `version` (part of the cache key), optional `defaultVoice`, optional `free` (see 12), `voices()`, optional `estimate(text, voice, options)` → `{ cost, currency, characters? }`, and `synthesize(text, voice, options, context)` → `{ file, model?, notes? }`, a mono 16-bit PCM WAV under `context.outDir`. `context` carries `outDir`, `signal`, `ensureBinary` and `progress`. Plugins register it with `registerSpeechProvider` and declare it in `contributes.speechProviders`. The addition is additive, so `PLUGIN_API_VERSION` stays `"1"`; a manifest that declares `speechProviders` fails to load on hosts before this ADR (strict manifest), which plugin authors must know.
3. **One host lookup for both provider kinds.** `PluginHost` finds transcription and speech providers through one private lookup (trust, declared-but-broken plugin, not-found error with the loaded ids); each kind only names its maps, its manifest list, its error code and its install hint.
4. **Built-in providers come before plugin ones** and need no trust. Slice 1 has the **stand-in** (`FRAMESHELL_SPEECH_STAND_IN=1` in `frameshelld`, tests only): free, deterministic, one sine tone per word with silence around, so length follows word count and trimming has work to do.
5. **First real provider: a machine-level `command` provider** (slice 2, settled): a TTS program the person installed, named in `<configDir>/config.json` under `speech.command` and nowhere else. `frameshell.json` is a strict schema with no such key, so one declared at project level is refused (the project fails to load, naming the key) and a downloaded project can never make Frameshell run a command, the same reason binary overrides are trust-sensitive. Built in, so it works in every project, trusted or not, and is looked up before plugin providers. Its shape: `run` (program and arguments, run without a shell; a relative program path resolves against `configDir`, a bare name is found on `PATH`), optional `voices` (ids, or `{ id, label, languages }`; absent = any voice id passes), `defaultVoice`, `version` (part of every take's cache key: bump it when the program or its model sounds different) and `timeoutSeconds` (default 120). The spoken text goes to stdin as UTF-8; `{voice}`, `{language}` and `{out}` inside an argument are replaced, and the program writes a mono 16-bit PCM WAV to `{out}` or, when no argument has `{out}`, to stdout. The project chooses the provider, voice, language and text, so they reach the program as data only: the text on stdin, and a voice or language that starts with `-` or holds a control character is refused before anything runs. A non-zero exit fails the line with `SpeechFailed` carrying the end of stderr; a program past its timeout, or still running when the daemon stops, is killed. The config is read on every call, so editing it needs no daemon restart. There is no shell: on Windows a `.cmd` or `.bat` cannot be the program.
6. **Cloud providers** come later as plugins, with the person's key from an **environment variable only** in v1 (works for CLI, daemon and app alike); the OS keychain later. Keys never reach project files, journal entries, progress messages or error data.
7. **Voiceover script = a script in `scripts/` with `voiceover: true`**, read with the shoot-script line rules (`parseVoiceoverScript` shares `parseShootScript`'s scene and line reading: one line per non-blank text line, `**Name:**`, `[LABEL: …]` cues never read). Frontmatter adds `language`, `provider`, `voice`. Each line has two forms joined by position: `display` (as written, digits kept, for captions) and `spoken` (what the voice reads). They differ by respellings `{display|spoken}` and by numbers with digits spelled out in `language` (`es`, `en`) through `spellNumbersIn`, which wraps `spellNumber`: one number speller, no twin. Heading timings `(0:00–0:09)` work as in shoot scripts and stay out of anchors. A scene whose words need longer than its timing at 2.5 words/s (`VOICEOVER_WORDS_PER_SECOND`) warns: trim the text, never stretch the picture. Line ids are `<scene slug>-<n>`, n counting the scene's spoken lines only, so a cue-only line never shifts them. Ids are positional: inserting a line moves the old takes to the next ids (as `copied`) and overwrites the old file with different speech, so a clip already placed on it would change sound. Settled in slice 4 (decision 19): ids stay positional, `voiceover.generate` warns when it replaces a take that a clip plays, and `voiceover.place` re-places with `replace`.
8. **Generated takes are project media** in `assets/voiceover/<script slug>/<line id>.wav` (script slug as for shoot files, `shootSlug`), never in `.frameshell/cache`: a paid take is not regenerable for free. `gc` never touches `assets/`.
9. **The cache key travels inside the take.** Each take's WAV holds a RIFF chunk `fsvo` with its key (SHA-256 of key version, provider id and version, voice, options, spoken text) and what made it. A line whose file holds its key is `cached`; a key found in another file of the folder (a line that moved) is `copied`; otherwise it is `generated`. No index file to lose with `.frameshell/`, and a cloned project keeps its cache. A `.wav` there without the chunk (made or edited by hand) is the person's: the call refuses before generating anything, and never overwrites it. `TAKE_KEY_VERSION` bumps when what a key stands for changes.
10. **Trim head and tail silence** on the 10 ms energy envelope of ADR 0003, with its own named threshold: quiet = 38 dB below the take's loudest 10 ms (#470), kept 20 ms before the first sound and 30 ms after the last. A synthetic voice has no room noise, so a peak reference is steadier than ADR 0003's percentile threshold, which stays as it is. A take quieter than -60 dBFS throughout is kept whole with a warning. The 5 ms RMS and fades of #470 belong to the silence split (decision 17).
11. **`voiceover.generate { cwd, script, lines?, provider?, voice?, yes }`** is one mutating daemon method that waits for its result and reports progress as `progress` notifications (not a queue job: the cost refusal and the per-line states must reach the caller). Order: parse, refuse a script without `voiceover: true`, pick lines, resolve provider and voice (unknown ones name the valid ids), plan cache states, refuse foreign files, estimate the cost, generate line by line, write each take atomically, then import every written take with one `asset.import` call. Calls are serialized per project. A provider failure stops the run: the takes finished before it stay written and imported (they may have been paid for) and the error `SpeechFailed` lists them; the next call reuses them. The run is not tied to the caller: Ctrl+C in the CLI or a dropped MCP connection does not stop it (only the daemon stopping aborts it), so a long paid run keeps calling the provider and keeps the takes it finishes. Failures of the provider's `voices()` or `estimate()` also arrive as `SpeechFailed` (`line: null`).
12. **Paid generation needs an explicit confirm**, also when an agent calls it. A provider whose estimate for the lines to generate is above 0 makes the call fail with `ConfirmationRequired`, carrying the cost, characters and lines, until it is called with `yes` (CLI `--yes`, a dialog in the app later). **Unknown cost counts as paid** (decided on the review of slice 1): a provider without `estimate()` is paid at an unknown cost and gets the same refusal (`cost: null`, "may cost money"), unless it declares `free: true` on the contract. The stand-in and the `command` provider declare it; a plugin whose provider is local and free must too. When both exist the estimate decides. Only lines to generate matter: cached and copied lines need no confirm either way. Cached and copied lines cost nothing and need no confirm. What stops a second charge is the take mark on disk plus the per-project serialization: a retry waits for the first run and then finds every finished take `cached`. A client-sent `idempotencyKey` (only the app sends one; the CLI and MCP do not, and failed requests such as `SpeechFailed` are not remembered) adds a replay of the first result, nothing more. Lines of one call with the same key are said once and copied. The skill tells agents never to pass `yes` without the person's confirmation.
13. **Misread check.** Each take is round-tripped through the project's transcription provider and compared with the line (built in slice 3: decision 18). It needs the trusted whisper-cpp plugin; untrusted projects get generation without verification, and the result says so.
14. **Kokoro** stays the local candidate, behind a spike after the pipeline ships (ORT Web speed, Spanish quality). If it goes ahead, its G2P is our own TypeScript (rule-based Spanish, dictionary English): no GPL anywhere (no eSpeak NG, no `phonemizer`).
15. **Preview pitch** at clip speed other than 1 (the preview resamples, export uses `atempo`; #499) blocks only per-phrase tempo, not the first slices. Placement of phrases on markers and beats uses the TimeRef resolver of ADR 0029 (decision 19).
16. **Slices.** (1) contract and pipeline, no real voice: this ADR's points 2 to 4 and 7 to 12, CLI `frameshell voiceover generate <script> [--lines] [--provider] [--voice] [--yes]`, the MCP tool from the registry, the skill; (2) the `command` provider; (3) silence split and misread round trip (decisions 17 and 18); (4) placement on markers and beats (decision 19) and the app's cost dialog (decision 20); later cloud plugins and the Kokoro spike.
17. **Silence split into phrases (slice 3, as built).** `splitPhrases` (`packages/core/src/voiceover/split.ts`) cuts a take where its 5 ms RMS envelope (`energyEnvelope` with a finer hop: the one envelope builder, not a twin) stays 38 dB under its loudest 5 ms for 60 ms or more; each phrase keeps 20 ms before and 30 ms after its sound, which fit inside the shortest silence, so phrases never overlap; a take with no speech is one phrase. The constants are the split's own (`SPLIT_*`), like the trim's: ADR 0003's percentile threshold is tuned for recordings and stays as it is. A phrase is a range of the take (`{ from, to }` in take seconds), derived from the file on every call and never stored, so cached lines report theirs and a take the person edits is read as it is. Phrases are the cuts of phrase clips (`clip add --in from --out to`): the human corrects them by trimming those clips, which is why a phrase is a range of the whole take and not a file of its own, and why per-phrase tempo (clip `speed`, #499) can follow. The 12 ms fade of #470 is `PHRASE_FADE_S`, reported as `phraseFade`: the clip `fadeIn`/`fadeOut` that carry it sit on the frame grid in export (`pictureRamps`, the sound ramps), so applying 12 ms to a clip belongs to placement (slice 4), not to the split. Nothing is placed on a timeline here.
18. **Misread round trip (slice 3, as built).** `voiceover.generate` gains `verify` (default `true`; CLI `--no-verify`). After the takes are written and imported, `verifyTakes` (`packages/core/src/voiceover/verify.ts`) loads the project's transcription provider the way `transcribe` does (`transcription.provider` of `frameshell.json`, default `whisper-cpp`, its model and language settings; the voice's `language` wins, as its base code), hands it each take as a 16 kHz mono WAV (a take at another rate goes through the transcriber's own ffmpeg `AudioExtractor`) and compares the words heard with the line by `compareTake` (the shoot comparison, over a one-line script: spoken numbers and word normalization stay in `packages/schema/src/spoken.ts`, never copied). A line is compared as `spoken` and, when it has respellings, as `display` too, and the better match is reported, because a transcription writes `freim shel` as `Frameshell`. Each line gets `check { status, heard, misreads }`: `clean`; `doubtful` when every difference may be the transcription's (a number, a close spelling, a lost short word); `misread` otherwise. A take that shares less than half its words with its line is one `changed` (or `missing`) difference covering the whole line. Each phrase also carries the words heard inside it. The result's `verification` says whether it ran: it is **skipped, never a failure** when the project is not trusted (plugins do not load), has no transcription plugin, `verify` is false, or the provider fails (a run that fails after some lines keeps those checks and warns): generation may have been paid for, so nothing about checking can lose or block a take, and the reason names how to fix it. Cached and copied lines are checked too, so the call re-checks the project's takes without saying anything. The checks run inside the daemon's per-project serialization of `voiceover.generate`, and the temporary 16 kHz audio lives under `.frameshell/cache/verify/` where `gc` sweeps leftovers.
19. **Placement on markers and beats (slice 4, as built).** `voiceover.place { cwd, timeline, script, lines?, at?, start?, gap?, track?, replace?, dryRun? }` (CLI `voiceover place`, MCP `voiceover_place`) puts the takes of the lines on a timeline as phrase clips, in one transaction `Voiceover: <script> (<n> lines)` (one proposal in review mode; `revert` undoes it whole). It never speaks and never costs: it reads the takes `voiceover.generate` already wrote (a line with no take fails, naming it), cuts each with `splitPhrases` on every call and adds one `clip.add` per phrase (`in`/`out` from the phrase range, rounded to whole frames and clamped to the take's whole frames; `scriptRef` `<script>#<scene>`, so `script.outline` lists the clips under their scene). The track is `track`, else the audio track named `Voiceover`, made when absent. **Where a phrase goes:** the phrases of a line keep the spacing the take has (in frames); `at` maps a line id (`hook-1`, the same as `hook-1.1`) or one phrase of it (`hook-1.2`) to a time; a line with no `at` follows the previous phrase by `gap` seconds (`VOICEOVER_LINE_GAP_S`, 0.4 s); the first one starts at `start`, else right after the voice track's last clip, else 0. Every time (`at` values, `start`) goes through the shared TimeRef resolver (`resolveTimeRefAsync` with the timeline's grid loader: seconds, markers with `+s`/`-s`, `beat:N`, `bar:N`; nothing here parses a reference, and a failure is `InvalidOperation` naming `at.<key>`), so whatever the resolver learns, placement learns. A clip starts on the frame nearest the time, so the first sound follows it by the 20 ms of air a phrase keeps (under a frame at 50 fps or less). Voice never overlaps itself: a phrase that would start before the previous one ends, or on a clip already on the track, fails naming both, with nothing written. **Positional ids, settled** (decision 7): ids stay positional (versioned file names would break a take the person edits in place), so the two commands guard the seam instead: `voiceover.generate` warns, naming the clips (`file.uses`), when it replaces a take that timeline clips play, and `voiceover.place` fails when clips already play the takes of the lines it is asked to place unless `replace` is true, which removes those clips first in the same transaction (their phrase ranges no longer fit a new take). A take whose mark names other text than the line has now is placed with a warning. `dryRun` plans without writing. **Phrase fades (owner, 2026-11-13; applied since #585):** decision 17 leaves the 12 ms fade to placement, but a clip fade is whole frames (ADR 0018, `edgeTransitions` quantizes) and 12 ms is a frame only at 42 fps or more, so slice 4 shipped without it rather than apply a different fade. #585 added sample-accurate audio fades for any media clip (ADR 0018 amendment: `audio.fadeInMs`/`fadeOutMs`, the same ramp in export and preview), and placement now gives every phrase clip `PHRASE_FADE_MS` (12, from `PHRASE_FADE_S`) at both ends in its `clip.add`. `phraseFade` stays reported. The 20 ms lead and 30 ms tail each phrase keeps and export's 2 ms ramp on every audio edge stay as they are. Anchors (`at`) must run in script order: each phrase is checked against the one planned before it. Per-phrase tempo stays out until the preview pitch fix (#499). Not placed here: transitions 3 to 6 frames before a line ends (#470 notes), which need the picture.
20. **Cost dialog in the app (slice 4, as built).** The Explorer's context menu of a script (`scripts/**.md`, `isScriptPath`) offers "Generate voiceover…", which asks main (`files.generateVoiceover`) to run `voiceover.generate` with `yes: false` and `verify: false` (the misread check may download a transcription model the person has not agreed to; it stays with agents and the CLI). When the daemon answers `ConfirmationRequired`, main shows a native message box naming the provider, the number of lines, and the estimated total, or that the provider does not say what it costs; its buttons are Generate and Cancel, Cancel is the default, and only Generate sends the same request again with `yes: true` (`runVoiceover`, `apps/desktop/src/main/voiceover.ts`, the one place that retries). A free provider, and lines already generated, never ask. A box then says how many lines were generated and shows the call's warnings; a failure shows the daemon's message in an error box. Strings are in `shared/i18n/app.ts` (`voiceover*`) and `editor.ts`, English and Spanish. Without a cloud provider yet, the e2e test drives it with `FRAMESHELL_SPEECH_STAND_IN=paid` (`stand-in-paid`, the stand-in voice at 0.01 USD a word). Not in the app yet: placing, the misread report, progress while generating.

## Considered options

- **A. Keep decision 10, voiceover skill-only.** Rejected: every agent reinvents caching, trimming and the misread check, nothing works without an agent, and a paid generation never shows its cost first.
- **B. Contract and pipeline, first provider a plugin.** Taken in part: D is B plus a built-in machine-level provider, so voiceover works in untrusted projects without shipping a voice.
- **C. Kokoro built into core** on ONNX Runtime Web (like ADR 0022). Deferred: Spanish needs eSpeak NG (GPL-3.0); our own G2P has unproven quality. A spike comes after the pipeline.
- **A hash-to-file index in `.frameshell/`.** Rejected for the in-file mark: the index is lost with `.frameshell/` (not shared, not precious) and a fresh clone would pay again for every take.
- **Takes in `.frameshell/cache`.** Rejected: the cache must be regenerable for free; a paid take is not.
- **A queued job** (`job.list`) for generation. Rejected for slice 1: the cost refusal and the per-line result must reach the caller; progress notifications already cover long runs.

## Consequences

- SPEC: decision 10 changed, decision 39 added; §5.1 layout, §5.5 scripts, §7 CLI, §8.1 manifest, §8.2 extension points, §12 roadmap.
- Protocol: `voiceover.generate`, `voiceover.place`, error codes `SpeechProviderNotFound`, `SpeechFailed`, `ConfirmationRequired`, `contributes.speechProviders` in `plugin.list`; `PROTOCOL_VERSION` bump.
- Global config: `speech.command` in `<configDir>/config.json`, read with the binary overrides by one reader (`readGlobalConfig`, `packages/core/src/global-config.ts`; `InvalidGlobalConfig` when malformed).
- Schema: `contributes.speechProviders` (JSON Schema regenerated), `voiceover` added to the built-in command groups a plugin may not shadow, `parseVoiceoverScript` and `spellNumbersIn`.
- The speech provider sees only the spoken text and the options; it never sees project files, so a cloud plugin can send nothing else.
- The take mark makes `assets/voiceover/` safe to regenerate over: only files this pipeline wrote, unchanged, are ever replaced.

# Synthesized sound effects and music: a seeded synth in core, marked takes in assets/sound/, placement by anchor on time references

#463 (epic #451) asks for offline, seeded sound effects (click, tick, pop, whoosh, riser, thump, impact, shutter) and music (tempo, chords, sections, genre presets), written as WAV files under new names, placed on markers or events, the same file for the same seed, with loudness in range per kind. The ticket text proposed an official plugin `@frameshell/sound`. The owner decided on 2026-11-11: option A, every recommendation of the proposed decision accepted (the eight points below). It ships in slices; **slices 1 (the sound effects, `sound.sfx`), 2 (`sound.place`), 3 (music, `sound.music`), 4 (credits and docs) and 5 (more kinds) are built; the true-peak limiter of decision 8 was built in #519 and finished here.**

## Context (verified)

- No sound or music code existed. Core had no synth; the schema had no tempo and no beats file schema (ADR 0029 slice 2 defines it).
- A plugin command (`CommandContext`) has no daemon handle: it cannot import an asset, read a marker or add a clip, and plugins load only in trusted projects. SPEC §13 limits official plugins to a short list.
- Voiceover (ADR 0034) has the shape: WAV takes in `assets/voiceover/<slug>/`, each holding a RIFF chunk with its own cache key, a file without the chunk never overwritten, one `asset.import` for the new ones.
- `pcmWavBytes` wrote mono 16-bit only. `STYLE_DEFAULTS.sound` holds the relative levels (`musicUnderVoice` 12 dB, `sfxUnderVoice` 20 dB); ADR 0028 keeps the integrated target in `export.loudness`.
- Credits (ADR 0026): licence `own` needs no credit, but `credits.check` fails a placed asset with no entry once a ledger exists. Cross rule 6 of #451 says generated sounds record credits through that path.
- #478: take nothing from HyperFrames `media-use` (HeyGen account and network); build in core, reference tools are references only.

## Decision

1. **In core, not a plugin.** The synth lives in `packages/core/src/sound/`, exposed through daemon methods; the CLI group `sound` is built-in and reserved (`BUILTIN_COMMANDS`, cross rule 5), so plugins may not shadow it. It writes marked WAV takes into `assets/sound/` and imports them, like voiceover. No SPEC §13 amendment, and it works in untrusted projects. The same parameters and seed always give the same file (a PCM hash test per kind and variant; own transcendental functions if V8's ever differ across platforms).
2. **Kinds in v1:** `click`, `tick`, `pop`, `whoosh`, `riser`, `thump`, `impact`, `shutter`, three variants each, a family seed and seeded jitter (pitch 0.9 to 1.3, level within 1.5 dB). Glitch, braaam, swell, bell, notify and a logo sting came later (slice 5 as built).
3. **Placement by a role table.** Every take records `peakAt` in its RIFF chunk. Placement puts it on the cue (a TimeRef: marker or seconds) plus an offset from `SOUND_ROLE_OFFSETS` in `packages/schema` (click -11 ms, tap -60, knock -40, pop +30, whoosh peak +37, swell peak +42; a riser ends 75 ms before the hit), overridable with `--offset`.
4. **Credits.** An entry `licence: own`, author "Frameshell sound synth", only when the project already has a `credits.json` ledger.
5. **Caps warn, never refuse:** more than 2 sounds on one frame, gaps below the per-kind minimum (tick 66 ms, key 87, pop 114), the same take twice in a row; the same rules are lint rules for #457.
6. **Music writes an exact beats file** (`detector: "exact"`, confidence 1, downbeat phase), using the one beats file schema (cross rule 3 on #451).
7. **CC0 set:** not now; later an optional on-demand download (licence files read before pinning), never committed, recorded in the credits ledger.
8. **The 4x-oversampled true-peak limiter for export** is its own ticket.

Gain: clip `gain` relative to the voice from `style.sound.sfxUnderVoice` and `musicUnderVoice`, with role tiers 0, -4 and -8 dB; takes are normalised on write (sound effects to a fixed peak; music to -14 LUFS with peak at most -1 dBFS). Format: 48 kHz WAV, 16-bit mono sound effects (the whoosh is stereo), 24-bit stereo music; `pcmWavBytes` is generalised, not copied.

## Slices

1. **Sound effects:** `SFX_KINDS` and the role table in `packages/schema/src/sound.ts`, the synth, `sound.sfx`, CLI `frameshell sound sfx`, MCP `sound_sfx`, protocol bump. Built, see below.
2. **Placement:** `sound.place` on TimeRef cues (the shared resolver of ADR 0037), on the cuts of a track and on typing runs, with gain from the style and the warnings of decision 5; CLI `sound place`, MCP `sound_place`, skill reference of the placement grammar. Built, see below.
3. **Music:** a seeded 16-step sequencer (synthwave, lo-fi, minimal), sections, sidechain, `sound.music`, the exact beats file. Built, see below.
4. Credits integration for music takes and the remaining docs. Built, see below.
5. More kinds and the audition page (both built, see below); later: the CC0 set.

## Slice 1 as built

- **Method.** `sound.sfx { kind, variant = 1, seed = 0, pitch?, length? }`, mutating. It writes `assets/sound/<kind>-<first 8 hex of the key>.wav` and imports it with one `asset.import`; the result carries the file, `state` (`generated` or `cached`), `duration`, `channels`, `peakAt`, `peakDb`, `rmsDb`, the pitch used, the `imported` job and `credited`. One run per project at a time. Review mode is not involved: assets are not journaled (ADR 0019); the timeline change of slice 2 will be a proposal.
- **The take key** is the SHA-256 of the key version, kind, variant, seed and the caller's `pitch` and `length` when given. It is stored with the kind, variant, seed, the pitch and level jitter actually used and `peakAt` in the RIFF chunk `fssd` between `fmt ` and `data`. A file already at that name whose mark holds the key is `cached` and not written again; a file with no mark, or another key, is refused with `InvalidOperation` and never overwritten. Bumping `SFX_KEY_VERSION` makes new names, so old takes stay.
- **Synth.** Pure TypeScript at 48 kHz: a seeded Mulberry32 generator (seeded from a hash of the parameters), biquad filters with clamped coefficients, additive tones, saturation with `tanh`. Recipes use the numbers of the ticket's comments (click 1 ms high-passed burst plus a 2.3 kHz blip and a 520 Hz body, or two pings that fall to half pitch in 35 ms; pop glide 820 to 1720 Hz; thump sine 95 to 42 Hz saturated under a low-passed noise sweep; whoosh band-passed noise sweeping 160 to 350 up to 3400 to 6850 Hz with its peak at 45 % of its length, panned left to right; riser noise sweep plus a rising saw with exponential gain growth, cut at its peak; impact a deep falling sub, a crack and a dark tail; shutter two band-passed clacks 30 to 40 ms apart). It runs inline: the longest take (a riser of 6 s) takes tens of milliseconds, so no worker thread yet; the music slice will need one (`worker-task.ts`).
- **Anchor.** `peakAt` is where the take meets the picture: the transient of a hit, the peak of a whoosh (45 % of its length), the end of a riser. Build sounds have a lead, so their peak, not their start, falls on the cue.
- **Level.** The peak is normalised to -3 dBFS and then shifted by the seeded jitter (±1.5 dB), so it is always below -1 dBFS. Normalising to loudness is for music (slice 3).
- **Credits.** After the write, when `credits.json` exists the take gets an entry (licence `own`, author "Frameshell sound synth") unless it has one; a take made before the ledger existed is recorded the next time it is asked for. No ledger: nothing is written.
- **Shared code.** `wavBytes` in `transcripts/window.ts` writes any channel count at 16 or 24 bits; `pcmWavBytes` calls it with the same bytes as before, so voiceover and transcription windows are unchanged. The rule that a file without our chunk is never overwritten is the voiceover rule, copied in shape because the two marks differ.
- **Registry type size.** `TimelinePatchSchema` is typed by name (`z.ZodType<TimelinePatch>`): it is the inverse of every operation result, so its structure was written out in dozens of methods and the `methods` registry hit TS7056 with one more entry.
- Protocol 92.

## Slice 2 as built

- **Method.** `sound.place { timeline = main, cues?, cuts?, typing?, track? }`, mutating; at least one of `cues`, `cuts`, `typing`. It makes every take like `sound.sfx` (the same code, cached when current, serialised with other sound work of the project), then writes **one transaction** `Sound: 2 whoosh, 3 click` made of at most one `track.add` per audio track it needs and a `clip.add` per sound. In review mode that is one proposal (ADR 0019); `revert` undoes it whole, the new track included. Planning (`planSounds`) is separate from the writes (`runPlan`) and touches no timeline file; the daemon opens the transaction only when there is a sound to write.
- **Where.** A *cue* is `{ at, kind, … }` with `at` a TimeRef resolved by the shared resolver of ADR 0037 against the timeline as the caller sees it (this code parses nothing; `beat:` and `bar:` work the day that resolver builds them). `cuts` is the start of every clip after the first of a video, audio or program track, or the numbered ones in `which`. `typing` is a run of keys between `from` and `to`: `tick` (default) or `click`, 8 keys a second by default, at most 10, each interval jittered by ±10 % from a seed (so the cues of two keys are at least 90 ms apart, above the 87 ms of the key gap; whole frames can bring the placed keys closer, which `soundWarnings` checks on the anchors), the takes rotating through 3 variants and 2 seeds so one never repeats the one before it. At most 200 sounds per call; the whole call is refused before any file is written when a time, track or cut number is wrong.
- **Offset.** A sound lands at `cue + offset - anchor`, the offset from `SOUND_ROLE_OFFSETS` by `role`, or `offset` (ms) when given. A kind has a default role: `click` and `shutter` click, `tick` tap, `pop` and `thump` pop, `whoosh` whoosh, `impact` knock; a riser has none and ends 75 ms before the cue. The result reports the offset used.
- **Whole frames.** A clip starts on a frame and the engine keeps whole frames of a file (it cuts the source at the last frame boundary). So a sound lands within half a frame of where asked (the -11 ms of a click is lost at 30 fps, and 60 ms becomes 2 frames), a riser loses its last partial frame (its anchor is planned at the end of the last whole frame), and a sound shorter than one frame cannot be a clip: it is listed in `skipped` with the reason, never a failure of the call. No take is that short at 20 fps or more: `synthesizeSfx` pads every take to `SFX_MIN_LENGTH` (50 ms) with silence, so a 35 ms tick is a clip at 24 and 25 fps (this bumped `SFX_KEY_VERSION` to 2; takes made before stay as they are under their old names). A sound whose start would fall before the timeline is cut at its head (`in`) with a warning, or skipped when nothing would be left.
- **Tracks.** The sounds go on the audio track named `SFX` (made when absent) or on `track`. Clips on one track cannot overlap and the sounds of a whoosh and a click do, so a sound that does not fit goes on `SFX 2`, `SFX 3` and so on (found by name, else made); each new clip keeps a spare frame from its neighbour. Only the tracks the call used are listed.
- **Gain.** Clip `gain` = `-style.sound.sfxUnderVoice` plus the tier in `SOUND_TIER_OFFSETS_DB` (primary 0, secondary -4, texture -8 dB), or `gain` when given. The voice is the reference by convention: takes peak at -3 dBFS, and nothing measures the voice (per-asset loudness is ADR 0037 slice 3). A kind has a default tier: tick texture, shutter secondary, the rest primary; a typing run is texture. The linear gains of the ticket body (0.7 to 0.9, 0.45 to 0.6, 0.3 to 0.4) are superseded by this decision comment's dB tiers.
- **Variants.** A sound without `variant` rotates through 1 to 3 along the timeline, starting after the sounds of that kind already on the audio tracks, so the same whoosh is not twice in a row, within a call or across calls.
- **Warnings** (never refusals, decision 5), computed over the new sounds and those already on audio tracks (read from the `fssd` mark of each take): more than 2 anchors on one frame (`SOUND_MAX_PER_FRAME`); two ticks closer than 66 ms or two pops closer than 114 ms (`SOUND_MIN_GAP_MS`; two keys of a typing run closer than 87 ms, `SOUND_KEY_GAP_MS`, measured on the placed anchors); one take twice in a row in time order. Only warnings that involve a new sound are shown, the first 6 and then a count. The same function (`soundWarnings`) is what #457 can lint with.
- **Credits** are the slice 1 path: each take is recorded as `own` when the project keeps a ledger.
- **Stale.** The times are read before the takes are made and the timeline is read again after: a changed revision fails with `StaleRevision` and places nothing (the takes stay, they are cached).
- Protocol 100.

## Slice 3 as built

- **Method.** `sound.music { preset, bpm?, meter = 4, bars? | length?, sections?, chords?, accents?, seed = 0, place = true, at = 0, track?, gain?, timeline = main }`, mutating (CLI `sound music <preset>`, MCP `sound_music`). It makes the take (planned by `planMusic` in `sound/music-place.ts`, written by `generateMusic` in `sound/music-take.ts`), serialised with the other sound work of the project, and with `place` writes **one transaction** `Music: minimal 120 BPM, 16 bars`: a `track.add` when it needs a track, the `clip.add`, and a `tempo.set { clip }` when the timeline had no tempo. In review mode that is one proposal; `revert` undoes it whole. `place: false` writes and imports the take only (no timeline is read unless a time names a marker or the length comes from the timeline).
- **Length and parts.** Whole bars: `bars`, or the bars whose end is nearest to `length` seconds, or with neither, from `at` to the end of the timeline (`timeline.show`'s duration). Then a final hit: the first chord, a crash and a big kick on the downbeat after the last bar, ringing `MUSIC_TAIL_SECONDS` (2.5 s); the take is `bars × meter × 60 / bpm + 2.5` seconds. `sections` are `{ kind, bars?, at? }` in order (`arrangeSections`, pure): a part starts on the bar nearest its `at` (a TimeRef, through the same resolver as `sound.place`), else right after the part before (which then needs `bars`); the last runs to the end. Disagreements (a part with no bars, `bars` that do not match the next `at`, a part that starts before the one before it, a first part that does not start the track) are `InvalidParams` naming the bar, counted from 1 as `bar:N` is. Without `sections`: one bar of intro and outro from 3 bars, two from 8, and in between a full part, then from 8 bars a two-bar build into a drop (`defaultSections`). `accents` are times moved to the nearest beat. At most 128 bars and 300 s (`MUSIC_MAX_BARS`, `MUSIC_MAX_SECONDS`), so the longest render is about 10 s of work.
- **Sequencer** (`sound/music.ts`). `scoreOf` writes every note of the track from the spec, then each note is rendered into a stereo mix with a reverb send. 16 steps a bar in 4/4 (4 a beat, any meter from 2 to 7). Presets (`MUSIC_PRESET_DEFAULTS`, the owner's numbers): `synthwave` 118 BPM, Am F C G, two band-limited saws per chord note 0.4 % apart through a low-pass, a saw bass on eighths with a sub an octave down and a low-pass that opens over the bar, a kick on every beat, snare and clap on the backbeat, offbeat hats; `lofi` 78 BPM, Dm9 G13 Cmaj7 Am7, an electric piano (sine and a fading second harmonic, tremolo), a round bass, a lazy kick, every odd 16th swung 16 %, vinyl clicks and hiss, the whole mix low-passed at 3.2 kHz; `minimal` 110 BPM (ours), FM mallet stabs (modulator 4 times the pitch), a plucked bass on a seeded 16th pattern, metallic hats from six square waves, no pads. Chords are a root and a quality from `MUSIC_CHORD_QUALITIES` (one per bar, repeating); tones above a ninth fold down an octave. The melody is a two-bar seeded walk on the minor pentatonic of the first chord (the relative minor when it is major), denser on the beat (a note on 50 % of beats, 32 % of the other eighths, 12 % of the other sixteenths, scaled per preset), one motif for `full` and a denser one for `drop`.
- **Parts as played.** `intro`: pad and hats. `full`: everything. `dark`: pad darkened, a sustained sub and a soft kick on the first beat and the half bar, nothing else. `build`: drums, bass, pad, a motif climbing the pentatonic (eighths, sixteenths in its last bar), a clap roll (on the beat, then eighths from its second half, sixteenths in its last bar, louder as it goes) and a noise riser that ends `SOUND_RISER_END_BEFORE_MS` (75 ms) before the next part, cut at its peak. `gap`: one stop-time hit (big kick, crash, a short chord) on its first beat and nothing else, so the next downbeat lands hard. `drop`: everything, a crash and a big kick on its first beat. `outro`: half time (kick on the first beat, snare on the half bar), pad and a held bass.
- **Mix.** The bass is ducked by the kick, 45 % with a 70 ms recovery. The reverb is a convolution with a synthetic impulse (decaying noise, a different draw per side, 20 ms pre-delay, low-passed at 5 kHz; 1.6 s for synthwave, 1.2 for lo-fi, 1 for minimal), by FFT overlap-add on the one FFT (`fft.ts`): the send is real, so one complex transform convolves it with the left impulse in the real part and the right in the imaginary. High-pass at 30 Hz, the last 50 ms faded.
- **Loudness** (`sound/loudness.ts`, pure). BS.1770 integrated loudness at 48 kHz (K-weighting, 400 ms blocks every 100 ms, gates at -70 LUFS and -10 LU), a look-ahead limiter (the gain each sample needs, its minimum over the next 5 ms averaged over 5 ms, a 60 ms release, so the ceiling holds at every sample), and a loop of gain, limiter and measurement, at most three passes or to within 0.15 LU. Takes come out at -14 LUFS with the sample peak at -1 dBFS. ffmpeg's `ebur128` reads the same loudness to within 0.1 LU (tested within 0.3); its **true** peak is up to 0.4 dB higher (-0.6 dBTP on a synthwave take): inter-sample overs are what the export's oversampled limiter (decision 8, built in #519, see slice 4) is for.
- **The take** is `assets/sound/music-<preset>-<first 8 hex of the key>.wav`, 48 kHz 24-bit stereo, with the `fssd` chunk holding `kind: "music"`, the key, the spec (preset, bpm, meter, sections, chords, seed, accents), `hitAt`, `lufs` and `peakDb`, so a cached take reports its facts without rendering again. The key is the SHA-256 of `MUSIC_KEY_VERSION`, the preset, bpm, meter, sections, chords, seed and accent beats, after defaults are filled (the same arguments written out give the same file). Cached, never overwriting a file without the mark, and credited as in slice 1. It renders in a worker thread (`sound/music-worker.ts`, the shared `worker-task.ts` runner): about 0.4 s for 19 s of synthwave and 3.5 s for 100 s of lo-fi on an Apple M3 under load.
- **The exact beats file.** Beside the take, `beats/sound/music-<preset>-<key>.beats.json` (the beats store's naming, `resolveBeatsFile`): `detector: "exact"`, `confidence: 1`, `downbeat: 0`, the bpm and meter, beat `i` at `60 i / bpm` seconds (microseconds) through the final hit, and as `onsets` the final hit, the accents and the first beat of every drop and gap. `assetHash` is the SHA-256 of the WAV bytes, so `beats.show` says `current`. A grid that is already exact for these bytes is kept with its `edits`; any other (missing, measured, stale) is replaced. `music.fit` finds the final hit of a generated track on its energy and snaps it to that onset: a four-bar synthwave take fitted to a marker lands its hit at 8.000 s with confidence 0.63.
- **Placement.** The clip starts at `at` on the frame grid, on the audio track named `Music` (made when absent), or `Music 2`, `Music 3`… when that time is taken; `track` names one, refused when its time is taken. Gain is minus `style.sound.musicUnderVoice` (12 dB), or `gain`. When the timeline has a tempo already it is kept, with a warning naming what it follows. The times are read before the take is made and the timeline again after: a changed revision fails with `StaleRevision` and places nothing (the take stays).
- Protocol 112.

## Slice 5 as built: more kinds

- **Kinds.** `SFX_KINDS` grows by `glitch`, `braaam`, `swell`, `bell`, `notify` and `sting` (the logo sting chirp), three variants each, same seed, jitter, level and key rules as slice 1. New kinds only: no recipe of the first eight changed, so `SFX_KEY_VERSION` stays and takes already written keep their names.
- **Recipes** (`sound/sfx.ts`, the numbers of the ticket's comments). `glitch`: 5 to 9 slices of 25 to 40 ms every 34 to 50 ms (variant 1: 7 of 32 ms every 42 ms), each a band-limited square or saw at a seeded frequency between 220 and 2600 Hz, anchor on the first slice. `braaam`: five saws detuned -18 to +19 cents on a root (C2, A1, D2 by variant), a low-pass that opens 250 to 1850 Hz and closes to 380 Hz, a saturated sub, 1.6 to 2.2 s (variant 1: 1.85 s), anchor on the onset. `swell`: band-passed noise sweeping up under a root and its fifth, gain growing as a power of 2.5 to a peak at 85 % of its length and a short release; anchor on the peak, `length` 0.5 to 3 s (`SFX_LENGTH_RANGE`). `bell`: four inharmonic partials (1, 2.76, 5.4, 8.93 times the base) dying faster the higher they are. `notify`: a tone near 2 kHz with a partial at 3.4 times its pitch, one note or two. `sting`: a chirp falling 1.5 kHz to 150 Hz in 70 to 100 ms into a 64 to 80 Hz hum with a second harmonic, anchor where the chirp lands on the hum (variant 1: 85 ms).
- **DSP.** `sawBlep` and `squareBlep` (PolyBLEP, `sound/dsp.ts`) give the glitch and the braaam waveforms that do not alias under a filter sweep.
- **Placement** (`SOUND_DEFAULT_ROLES`, `SOUND_DEFAULT_TIERS`). `glitch` role `click`, tier secondary; `braaam` `knock`, primary; `swell` `swell` (peak +42 ms), secondary; `bell` and `notify` `pop`, secondary; `sting` `knock`, primary. No new minimum gap.
- **Tests.** The PCM hash table has an entry per new kind and variant (seed 7); the generic cases cover peak, head-room, faded tail and mono output for them; length and anchor of each are asserted.
- Protocol 139 (the kind enum of `sound.sfx` and `sound.place` grew).
- Not done: the CC0 set, the audition page, the energetic music preset. The owner listens to the new kinds before they are relied on.

## Slice 4 as built: credits, docs and the export limiter

- **Credits.** Music takes are recorded as `own` (author "Frameshell sound synth") exactly like sound effects, only when `credits.json` exists; no change was needed after slices 1 and 3, which share `generate`'s credits path. The docs listed in the consequences are written: SPEC decision 43 as built, GLOSSARY (music take, section, true-peak ceiling), the doc map rows of CLAUDE.md.
- **True-peak limiter** (decision 8, its own ticket #519, completed in the last slice of #463). The export's mux runs `loudnorm` pass 2, then `aresample` to the export rate, 4x oversampling, `alimiter` (`level=false`, `latency=true`) and back (SPEC §3.5 step 4). Two things the first version left over:
  1. **Loudness.** The limiter takes loudness off a transient-heavy mix (0.6 LU on the first fixture, 2.4 LU on a hostile burst train). When the limiter can engage (`limiterEngages`: the measured true peak plus the gain `loudnorm` applies, target minus measured loudness, reaches the ceiling; its `target_offset` is not that gain) the export measures the limited mix again (`limitedAnalysis`: the same chain plus `loudnorm` in analysis mode, writing `limited.json`), adds the missing difference as `volume` in front of the limiter and measures once more, at most 3 measurements (`LOUDNESS_PASSES`), at most +3 dB (`MAX_TRIM_DB`, past which the limiter eats the gain), stopping within 0.15 LU (`LOUDNESS_TOLERANCE_LU`) and keeping the measurement closest to the target (`settleTrim`, pure and tested with fake meters; after two measurements it divides the error by the loudness each dB of trim really gained, since a limiter that eats most of the gain needs more than one-for-one steps; the trim is also capped at -3 dB; the re-measures report progress inside the mux step). `muxStep` takes the trim and runs the same chain, so what was measured is what is written. This is the ticket's "re-measure up to 3 times to ±0.15 LU", applied in the export; the sound takes use the same loop on raw samples (`normaliseLoudness`). A mix the limiter cannot touch skips it and costs nothing.
  2. **Ceiling per codec.** One -1.5 dBFS did not suit every encoder. `TRUE_PEAK_CEILINGS` in `export/true-peak.ts` holds a ceiling per codec and bitrate class as data: PCM -1.2 dBTP, Opus -1.8 from 64 kbps, AAC -2.3 from 160 kbps, -4.9 below (the Opus class below 64 kbps too). Each is -1 minus the worst overshoot the encode added to full-scale bursts in 24 test files measured with ffmpeg 9.0.2 (PCM +0.1 dB, Opus +0.7, AAC 160-320 kbps +1.2, AAC 96-128 kbps +3.0 to +3.8, Opus 48 kbps +3.7) minus 0.1 dB for the meter's resolution; the basis is AES TD1008 section 4 (-1 dBTP at the codec input of a lossy stream). The plan carries it (`RenderPlan.audio.truePeak`, from the preset's codec and, for a `final` export, the 320 kbps AAC it uses). Real speech and music overshoot far less than the fixture, so the ceilings err on the safe side; the re-measure gives back the loudness they cost.
- **Tests.** `true-peak.test.ts` (table, `limiterEngages`, `settleTrim`); compiler tests for the ceiling per preset and the trim in `muxStep` and `limitedAnalysis`; a real-ffmpeg export of two transient fixtures (a bed near the target, and a quiet one at about -33 LUFS whose `target_offset` hides the peak) as AAC 320, AAC 128 (not the quiet one: its -4.9 dBTP ceiling costs more than +3 dB gives back), Opus and PCM, each at most -1 dBTP and within 0.15 LU of the target.
- Not done: the CC0 set, the audition page and the energetic music preset (decision 7 and slice 5), postponed by the owner. A burst train above 5 kHz can still exceed the AAC and Opus ceilings.
- **Known limit: the trim cap.** The loudness loop adds at most +3 dB (`MAX_TRIM_DB`). When that cap binds, the export misses the target by more than 0.15 LU, below it: a transient-heavy mix that is quiet before the limiter (about -33 LUFS in the fixture) at AAC 128 kbps, whose ceiling is -4.9 dBTP, needs more than +3 dB to give back what the limiter takes, so the file ends under the target. Owner decision 2026-11-16: `MAX_TRIM_DB` stays +3 dB (past it the limiter eats the gain); the limit is documented (SPEC §3.5 step 4, CHANGELOG) and the export says nothing about it. The AAC 128 test leaves the quiet fixture out for the same reason.

## Audition page as built

Owner decision 2026-11-17 (Q2 of wave 19): an in-app, read-only dialog, not a web page; players, a spectrogram computed by the daemon on the one FFT, loudness from `LoudnessStore`.

- **Method.** `audio.inspect { assets[1..32], spectrogram = false }`, read-only (no journal, no transaction, not `mutating`). Per file: `duration`, `lufs`, `truePeak` and `range` from `LoudnessStore.reading` (the cache `music.candidates` and `duck --level` use, so a file is never measured twice), and `take` from the `fssd` mark in the first 64 KB of a WAV (`kind`, `seed`, and `variant` for a sound effect or `preset` and `bpm` for music; null for any other file). EBU R128 reads a sound shorter than one 400 ms gating block as silence, and most sound effects are (a pop, a click): for those `lufs` is the loudness of the one block that holds the sound (padded with silence, decoded at 48 kHz, through the synth's BS.1770 meter `integratedLoudness`) and `shortSound` is true, so a pop and a whoosh can be matched. A file whose loudness cannot be read (no sound, undecodable) is listed in `skipped` with the reason and the call goes on; a missing file or one outside the project fails the call (`AssetNotFound`, `OutsideProject`), as do the `Binary*` errors. An MCP tool (`audio_inspect`) through the registry; no CLI command.
- **Spectrogram** (`media/spectrogram.ts`, pure). The first 600 s of the sound folded to mono at 32 kHz by ffmpeg into a temp WAV outside the project, then in a worker thread (`media/spectrogram-worker.ts`, the shared `worker-task.ts` runner): 1024-sample Hann windows through `fft.ts`, one column per 5 ms of sound up to 400 columns (a column of a long file is the mean power of at most 4 windows spread over it), 64 rows spaced in equal ratios from 40 Hz to 16 kHz (the loudest bin in the band, or the power read between the two nearest bins when the band is narrower than a bin, the lowest rows). Whole dB relative to a full-scale sine, floor -96. A sine shows in its own row and more than 50 dB lower beyond an octave from 1 kHz up; below a few hundred Hz a 31 Hz bin spans several rows, so the low end is blurred. Opt-in because it is about 25 000 numbers a file: for drawing, not for an agent to read.
- **No disk cache, no gc kind.** Measured on a busy Windows machine: about 1.2 s for 27 s of 24-bit music and 1.7 s for a 3-minute MP3, most of it ffmpeg; a sound effect is a fraction of that. The last 32 spectrograms stay in memory by content hash, so reopening the dialog does not decode again. The wire `GcEntry` kind list is unchanged.
- **Dialog** (`components/AuditionDialog.tsx`, store `renderer/src/audition/store.ts`, pure model `audition/model.ts`, strings `shared/i18n/audition.ts`). It opens from the Explorer's right-click menu on two or more selected sound files (Audition N sounds…), on a folder with two or more sound files directly in it (its subfolders are not read: `assets/` would take every song), and on a `Music <rank>` audio track of `music.candidates` (the first clip of every such track, by rank). At most 32 files, the method's cap (`AUDITION_MAX`, held equal to `AUDIO_INSPECT_MAX` by a test). Each row: play/stop, the spectrogram painted one pixel a cell on a canvas (low frequencies at the bottom), loudness and true peak, the take's kind and seed, and **Use this**. **Match loudness** plays every row at the quietest one's loudness (gain = target minus its own LUFS, never a boost; a silent row stays at 0 dB) and changes the level of the row playing at once. **Use this** selects the file in the shared selection (the Explorer highlights it) and closes; it never edits a timeline in v1.
- **Playback** is the People panel's player (`people/voice-play.ts`), generalised with a gain: the PCM sidecar fetched with an HTTP range and played through Web Audio of the window the button is in, one sound at a time across the app, pausing the timeline. A file not ingested yet has its button disabled until its sidecar exists.
- **Shared code.** The modal keys and focus of the voiceover dialog moved into `components/modal.ts` (`useModal`), used by both dialogs; the audition dialog reuses the voiceover dialog's frame classes.
- **Tests.** `core/test/audio-inspect.test.ts` (sines at 1, 1.234 and 5.555 kHz each in their row, silence on the floor, the column cap, the method through a real daemon: loudness, marks, skipped, the result schema); `apps/desktop/test/audition-model.test.ts` (match gains, file lists, candidate tracks, colours); e2e `audition.spec.ts` (two generated takes from the Explorer, match on and off, play/stop, Use this, the folder menu, Escape).
- Protocol 166 (one new method).
- Not done: the CC0 set and the energetic music preset (postponed by the owner); a CLI command for `audio.inspect`; placing the chosen file from the dialog.

## Considered options

- **B. An official plugin `@frameshell/sound`** (rejected): plugin commands cannot reach the daemon, so placement needs a new plugin API surface for every plugin; the plugin is lost in untrusted projects; a second SPEC §13 amendment right after ADR 0035; against #478.
- **C. HyperFrames `media-use`** (rejected, #478): needs an account and the network.
- **D. A bundled CC0 set instead of synthesis** (deferred, decision 7): downloads on demand with credits, later; the owner notes that synthesis reads cheap next to real recordings, and the audition page of slice 5 lets the person choose.

## Consequences

- Core grows by about 600 lines of DSP for the sound effects and about 1 200 for music (sequencer, voices, reverb, loudness, placement).
- The same seed gives the same samples only on machines whose V8 has the same `Math.sin`, `exp`, `cos` and `tanh`; the hash test in CI on macOS, Linux and Windows shows the day they differ.
- `assets/sound/` is project media: `gc` never touches `assets/`, and a clone carries the takes and their keys.
- A project with a ledger gets one `own` entry per take; a project without one gets none and no export warning.

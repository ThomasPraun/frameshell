# Formats of a project: one edit, re-blocked per format

Ticket #469 (epic #451) asks for 16:9, 1:1, 4:5 and 9:16 deliveries from one project, each re-blocked rather than letterboxed. The owner decided on 2026-11-10 (option A of the proposal on #469, every recommendation accepted): formats live in the project, the automatic layout comes first, and sparse per-format overrides follow where it is wrong. This ADR records that decision. It amends SPEC §3.5 step 4 (crop-to-fill was "a later option"), §5.2 and §6.5.

## Context (verified in the tree, 2026-11-10)

- One frame per project: `frameshell.json` has a single `resolution` (`packages/schema/src/project.ts`). A timeline has no size of its own.
- Export sizes came from presets (`youtube-1080p`, `youtube-1440p`, `vertical-1080x1920`). Media whose aspect differs from the output was letterboxed (`layerRect` fits, then maps `transform.x/y` from project pixels to output pixels). The compiler already took any output size.
- Multicam re-blocks already: each angle's `reframe` keys are a point in the source, and `shotLayers` lays the tiles out per output size (ADR 0016).
- Generated clips render at the project size (`RenderContext.width/height`), and the clip cache key holds `fps`, `width` and `height`, so a render at another size is another cache entry with no key change.
- Subtitles size from the frame's short side (`subtitleLayout`), so captions keep their pixel size in 9:16.
- Timing never depends on the frame: clips, transitions, keys and audio are format-free.
- Measured rules from the #469 comments: canvases 1920x1080, 1080x1080, 1080x1350, 1080x1920; the first format listed is the primary one; vertical type is about landscape x 1.3-1.35; a variant is never a crop of another and its layout is chosen by the variant's name.

## Decision

1. **Formats are project-wide**, in `frameshell.json` `formats: [{ id, width, height }]`.
2. **The first format is the primary one and equals `resolution`.** A project without `formats` has one format, its resolution, with the built-in id of that canvas or `<width>x<height>`. Existing projects, and the primary output of every project, are unchanged.
3. **In a format other than the primary, an untransformed full-frame media clip covers the frame**: the centre of its picture with the frame's aspect, scaled to fill it (later around a #459 focus point). A clip with a transform or picture keys keeps its fitted placement, offsets mapped from project pixels as before. Multicam program tracks keep their own per-output layout (`shotLayers`, `reframe`): the cover rule skips shots. Generated clips are not cropped: they render at the format's size (decision 12). **A source with alpha on an upper track (a webm or ProRes title, a PNG overlay) is not cropped either: it is fitted whole until per-format overrides exist (decision 13 of #469); on the base track alpha does not change the rule.** The probe records the fact (`media.video.alpha`).
4. **The format owns the frame; a preset gives codec, bitrate and loudness.** A preset asked for whose aspect differs from a format rendered is refused. A preset of the format's aspect sets the output size when asked for, or in the primary format (so `youtube-1440p` still scales a 1080p project, and a 4K project keeps its default preset's size). A default preset (`export.defaultPreset`, else `youtube-1080p`) of another aspect is rendered at the format's own size.
5. **Per-format overrides** (slice 4) may carry `transform`, picture keys, `hidden`, `props`, `elements` and subtitle `style`, never timing or audio. Focus per format is the face framing `clip reframe --format` writes into these fields (slice 5, owner 2026-11-13); a separate `focus` point for the automatic cover is not built.
6. **Built-in ids**: `16x9` 1920x1080, `1x1` 1080x1080, `4x5` 1080x1350, `9x16` 1080x1920, each with exactly that canvas. Custom ids are allowed (`web-1600x900`). Ids are lowercase letters, digits and `-`; `png`, `jpg`, `jpeg` and `webp` are reserved because `frameshell frame --format` takes both.
7. **Captions in vertical formats are 1.3x larger** (the low end of the measured range), except in the primary format, whose output stays byte-identical.
8. **The HyperFrames adapter rewrites `data-width`/`data-height` on its render copy** (slice 3, spike in [Evidence](#evidence-hyperframes-render-at-a-format-size-slice-3)). It sets the size of the first `data-composition-id` root of the copied entry (outside scripts, styles and comments) to the render's `RenderContext` width and height, and nothing else, when the declared size has the project resolution's aspect and the render's aspect differs from it by more than 1 % (the `sameAspect` rule of export). Of the same aspect, with no declared size, or for a composition of its own shape (a square card or a strip in a 16:9 project), the copy stays as written: the render keeps the composition's own size and export scales it, so the primary output of an existing composition is unchanged. Sub-compositions keep their sizes. The runtime's `stage()` and `pick()` (ADR 0033) read the root, so a template lays out for the format it renders in.
9. **The preview's 9:16 toggle becomes a switcher over the declared formats** (slice 2, built).
10. **Handles, Pick and element mode in a format write to that format's override** (slice 4; handles and the inspector built, Pick and element mode not yet).
11. **A daemon method edits formats**: `format.list`, `format.add`, `format.remove` (CLI `frameshell format list|add|remove`), journaled, undoable, routed through review mode.
12. **Background renders cover only the primary format.** Other formats render on export, on `frame` in that format, or when the preview switches to them (`clip.renders` with `format`, slice 3; the preview asks since slice 5). `gc` keeps the cached renders of every declared format.
13. **A preset may be a box instead of a frame** (amendment of ADR 0039, #474 slice 2): `video.fit: "inside"` makes `video.width` x `video.height` a bounding box. The format's frame is scaled down to fit it with its own aspect (never up, odd sizes kept) and the aspect check of decision 4 does not apply: the `gif` preset renders every format, 16:9 as 1200x675 and 9:16 as 675x1200. A default preset with `fit` is never reported as overridden by the format, since it follows it. #500's letterbox key joins this amendment.

One pure function, `resolveFormat(timeline, project, id)` in `packages/schema/src/formats.ts`, says how a timeline lays out in a format (frame size, `cover`, `captionScale`, and the timeline with that format's overrides applied, `formatTimeline`). Export, `frame` and the preview read it, later review too. Next to it, `formatCrop` says which source pixels of a clip cover the frame (null where the clip stays fitted) and `scaledCaptions` sizes the captions; the compiler and the preview both call them, so neither keeps its own copy of decisions 3, 7 and 13.

## Considered options

- **One timeline per format nesting a shared edit timeline.** Rejected: a nested timeline is placed as one picture, so footage inside it cannot be re-blocked per format, and per-format captions need another mechanism.
- **Fork a timeline per format.** Rejected: every cut or text fix after the fork must be repeated in each copy, which is the drift the epic exists to remove.
- **Automatic re-block only, no overrides.** Kept as the first layer; rejected as the whole answer because a lower third placed for 16:9 cannot be moved for 9:16 alone and a person correcting the timeline would have no per-format handle.
- **`render --formats` picking a preset per aspect by itself.** Rejected (decision 4): the format owns the frame, so no preset table per aspect is needed.

## Consequences

- **Schema:** `formats` in `ProjectConfigSchema`, checked after parsing (primary equals `resolution`, unique ids, built-in canvases, even sizes after the first, none in image projects). `ProjectConfigSchema` is strict, so a host older than this ADR refuses a project that has `formats`. JSON Schema regenerated.
- **Compiler:** `RenderInput`/`FrameInput` take `variant` (`cover`, `captionScale`); absent, plans are byte-identical to before, so every existing golden stays. `ExportSource.video.alpha` (from the probe, `MediaProbe.video.alpha`, absent in manifests cached before it: they are probed again) turns the cover off for upper-track clips; `formatCrop` decides it, for `layoutTimeline` and the preview alike. Covering is a `crop` in source pixels (`coverCrop`, the multicam tile crop) before `scale` to the frame.
- **Clip renders:** `ClipRenderer.ensure` takes a size; the cache key already holds it, so the key recipe and `CACHE_LAYOUT_VERSION` do not change. `gc` keys every clip at every declared format size.
- **Wire** (`PROTOCOL_VERSION` 79): `render` takes `formats` (one job per format, file `<name>-<format>.<container>`, `renders` in the result); `frame` takes `projectFormat` (its `format` stays the image type); new `format.list`, `format.add`, `format.remove`; new error `FormatNotFound`. CLI `render --formats`, `frame --format <id>`, `format list|add|remove`; MCP tools follow from the registry; the skill documents them.
- **Behaviour change:** `render --preset vertical-1080x1920` (or `frame --preset`) in a 16:9 project is refused with a hint to `format add 9x16` and render that format. A vertical project without an explicit preset now exports at its own size instead of a letterboxed 1920x1080. An `export.defaultPreset` of another aspect than the project likewise gives only codec, bitrate and loudness: a 16:9 project with `defaultPreset: vertical-1080x1920` exports at 1920x1080 instead of letterboxed into 1080x1920, and that render's `warnings` say so.
- **Format journal:** each change is a line in `.frameshell/history/project.config.jsonl`, written before `frameshell.json`, and the result names the call that undoes it (`undo`). Removing the last other format removes `formats`, so `frameshell.json` is byte-identical to before the first add. Since ADR 0036 a line is a keyed config operation (`doc`, `patch` of `format:<id>` keys, `tx`, `txLabel`, hash chain); lines written before it (formats before and after) are read as such.
- **Decision 11 stopgaps, both gone:** since ADR 0036 slice 1 format changes join the caller's transaction, `history` lists them, and `revert` of their `op` or `tx` (and `tx abort`) undoes them; `revert` no longer refuses them with reason `format change`. Since ADR 0036 slice 2 review mode holds them: a format change by anyone but the app (`ui`) waits in the transaction's proposal (`proposal` in the `format.add`/`format.remove` result) instead of being refused with ProposalState `forbidden`.
- **Preview (slice 2, as built):** the 9:16 toggle and its fixed 1080x1920 frame are gone. With two or more formats in `frameshell.json` (followed live; an invalid `formats` keeps the last good list), a switcher in the transport bar lists them, primary first. The format shown comes from `formatOf` (the format half of `resolveFormat`); `compileProgram` takes it and gives each media or still span the `cover` crop of `formatCrop`, which the engine draws over the whole canvas (the crop scaled from probed source pixels to proxy pixels); the subtitle overlay draws `scaledCaptions`. Multicam shots keep `shotLayers` at the canvas size. Generated clips were drawn fitted from their primary render until slice 5 brought the format's renders to the preview. Handles, Pick, element mode and live pages stay in the primary format and are off in the others (handles work there since slice 4). A project with one format shows no switcher, so a landscape project without `formats` no longer has a 9:16 view: `format add 9x16` gives it one. A parity test (`apps/desktop/test/preview-formats.test.ts`) checks against `compileFrame` that the preview covers and fits the same clips with the same crops in every format, and that captions get the size export burns.
- **Slice 3** (`PROTOCOL_VERSION` 104): the HyperFrames adapter sizes its render copy (decision 8; `plugins/hyperframes/src/frame-size.ts`, its `sameAspect` a hand copy of the schema's with a parity test, since a plugin ships only its own files). `clip.renders` takes `format` (an id of `format.list`): the states of that format's renders, with the missing ones queued, the way the preview switcher (slice 2) will ask; FormatNotFound for an unknown id. The cache key recipe and entry layout are unchanged (the key already holds the size), so `CACHE_LAYOUT_VERSION` stays 1 and primary renders keep their keys and pixels. Renders at another aspect cached by slice 1 builds (letterboxed, never released) keep their keys too: delete `.frameshell/cache/clips` in such a project to render them again. Live pages (ADR 0010) still show the composition at its own size, fitted into the format. Element adjustments (ADR 0021) are CSS px of the composition and apply unchanged to a resized layout until per-format overrides (slice 4) carry `elements`. A custom format of the project's aspect but another size (`web-1600x900`) renders each generated clip a second time with the same layout; accepted for now.
- **Slice 4, overrides (as built, `PROTOCOL_VERSION` 116):**
  - *Model.* A clip on a video track may carry `formats: { <id>: { transform?, keys?, hidden?, props?, elements? } }`; a subtitle track `formats: { <id>: { style } }`. Keys are `x`, `y`, `scale`, `opacity` only (no `gain`); `props` and `elements` only on generated clips; none on audio tracks or shots (shots lay out per format by angle `reframe`). The timeline schema refuses the rest. Overrides are plain JSON in the timeline file, so operations, inverses, the journal, revert and review mode treat them like any other field. An override of the primary format, or of a format `frameshell.json` no longer lists, is kept and ignored: adding the format back brings it back.
  - *Resolution.* `formatTimeline(timeline, id)` (in `formats.ts`, beside `resolveFormat`) gives the timeline as it plays in format `id`: the override's `transform` fields over the clip's (each one also drops the clip's own keys of that property), its keys replacing the clip's per property, `props` and `elements` merged key by key, a subtitle track's override style over its own. A hidden clip stays on its track at opacity 0 (its opacity keys dropped): export leaves its picture layer out and the preview draws nothing of it, while its sound, its transitions with its neighbours and the captions of its words are the primary's (decision 5: overrides never change timing or audio). A clip that dissolves from it fades in over what is below. It works on a timeline file and on a `timeline.show` view alike, and returns its input unchanged when nothing is overridden in `id`, so the primary output, every golden and every primary render key stay as they were. Covering (decision 3) is then decided on the resolved clip: a clip placed in a format is fitted there.
  - *Who reads it.* Export applies it to the timeline and to each nested timeline before flattening (`resolveNestedIn`), per format of `render --formats`, for `frame` with `projectFormat` and for `resolvedSubtitles` (review sheets). Clip renders key a clip with its override there (`clipInFormat`): `ensure` of the resolved timeline, `clip.renders` with `format`, and `gc`, which keeps the renders of every declared format's props. The preview resolves its view and nested views the same way (`viewsInFormat` in `useProgram.ts`) before `compileProgram`, and the subtitle overlay its tracks; the parity test covers overrides against `compileFrame`.
  - *Operations.* `clip.set` and `clip.key` take `format` (and `clip.set` `hidden`, `reset`); `track.set` takes `format` with `style`, and `reset`. `format` must name a declared format other than the primary (FormatNotFound, or InvalidOperation for the primary, from the project's formats in `EditContext.formats`). Timing and sound fields with `format` are refused. `props` with `format` replaces that format's props and is checked over the clip's own. `clip.key` with `format` starts from the clip's keys of the property; `clear` (or removing the last key) lets the format follow the clip's keys of the property again, unless the override's `transform` sets that property. A format edit that would change nothing (no fields, an empty `transform` or `style`, `reset` with no override there) is refused like the clip's own. CLI `--format <id>` on `clip set`, `clip key` and `track set`, `--hidden`/`--shown` and `--reset`; MCP follows from the registry; the skill documents them. `track.set` with `format` takes only `style`: hiding a track per format is not part of decision 5.
  - *Captions.* An override's style is drawn like the track's own: in a vertical format other than the primary, 1.3x larger (decision 7), its `size` included.
  - *Editing in a format (decision 10).* In a format other than the primary the preview's handles select and move clips there: boxes are laid out in the format's frame (`layerBox`, `layersAt` with `output`), and a drag sends `clip.set` with `format`. Covering footage has no placement of its own, so its handles start from the placement that fills the frame (the fit scale times fill over fit) and a drag stores all of it, keeping the picture's size. The inspector (clip and subtitle track) shows the format's values, sends its changes there, and offers "Hide in <format>" and "Use primary" (`reset`). Sound, transitions, glass and the followed track stay shared and edit the clip itself.
- **Slice 5, focus per format, mark, format renders in the preview (as built, `PROTOCOL_VERSION` 126):**
  - *Focus.* #459 shipped the face-following framing as `clip.reframe` writing placement and keys (`transform.scale`, `x`/`y` keys), not as a focus point the automatic cover centres on. Decision 5's `focus` is therefore that framing held per format: `clip.reframe` with `format` naming a declared format other than the primary (the default `9x16` too, once declared; `reframeTarget` in `packages/core/src/reframe.ts`) frames for that format's own aspect and writes into the clip's override there, through `clip.set` and `clip.key` with `format` in one transaction: the override's x, y and scale keys are cleared, its `transform` set (which drops the clip's own keys of those properties in that format), its `x`/`y` keys written. The clip itself, the primary and the other formats keep their framing, so each format follows the face its own way. The result names the format (`inFormat`). The primary's id, or an aspect (`9:16`; ids cannot hold `:`), frames the clip itself as before; its warning in a project of another aspect names `format add` instead of the `vertical-1080x1920` preset that decision 4 refuses there. No `focus` field exists: a focus point for the automatic cover is not built, since nothing produces one.
  - *Mark.* The timeline draws a small portrait frame in the top-right corner of a clip with an override in a declared format other than the primary (`markedFormats` in `renderer/src/timeline/layout.ts`); its tooltip names those formats. Overrides of the primary or of a removed format are ignored, so not marked.
  - *Renders in the preview.* The preview's clip-render states come from `clip.renders` with the format shown (`useClipRenders`), which keys each clip with its override there and queues the missing renders (decision 12): a generated clip plays its render at the format's size, with that format's props, fitted as export fits it; a slate shows while it renders. Until the read answers, the states of the format shown before stay.
- **Not covered by slices 1 to 5:** Pick and element mode in a format (they stay in the primary), live pages at a format's size, a focus point for the automatic cover, review per format (#457).

## Implementation plan (each slice ships and is tested alone)

1. Automatic layer for export: schema, `resolveFormat`, compiler cover and captions, renders per format and `gc`, `render --formats`, `frame --format`, `format list|add|remove`, this ADR and the SPEC.
2. Preview switcher over the declared formats, replacing the hard-wired 9:16 toggle, with a parity test against `resolveFormat` and the compiler. Built; generated clips show fitted until renders per format reach the preview.
3. HyperFrames resize spike and adapter change (done), `clip.renders` per format.
4. Per-clip and per-track overrides, `--format` on `clip set` and `track set`, editing in a format from the preview. Built: overrides, operations, export, renders, preview, handles and inspector; Pick, element mode and `focus` left (see Consequences).
5. `focus` per format (`clip reframe --format <id>` into the override), the timeline mark of overridden clips, the preview's renders per format. Built; Pick and element mode in a format left.

## Side effects

- **Existing exports:** unchanged for every same-aspect preset; goldens byte-identical. Changed: an explicit preset of another aspect than the project is refused (decision 4).
- **Plugin API:** `RenderContext.width/height` is now the size being rendered, the project's or a format's. Adapters that ignore it still work; their render is fitted (letterboxed) in that format.
- **Clip render load:** a render per generated clip per exported format, on the single clip queue. Background renders stay primary-only.
- **Not affected:** timing, operations and their inverses, the timeline journal, transcripts, the audio pass and loudness.

## Evidence: HyperFrames render at a format size (slice 3)

Measured on 2026-11-12 with `@hyperframes/producer` 0.9.30 and the managed `chrome-headless-shell`, macOS (Apple silicon), by `plugins/hyperframes/test/format-real.test.ts` (opt-in, `FRAMESHELL_TEST_REAL_HYPERFRAMES=1`).

- **The root's size decides the page.** The producer's compiler reads `data-width`/`data-height` of the first `[data-composition-id]` element as the composition's size, and the capture sets the Chrome viewport to it; its page runtime also reads them for the root. The output file has that size.
- **Nothing else needs editing.** The plain scaffold and every template write `html, body { width: <w>px; height: <h>px }` and a viewport meta with the scaffold size. Rewriting only the root's attributes gave the same frames as also rewriting the meta and adding a last `html, body` sheet: the scaffold's card at 6 % left, 10 % bottom of a 180x320 render from a 320x180 composition, alpha identical at every probed pixel, and the `lower-third` template byte-identical in both variants. The adapter therefore changes the two attributes only.
- **A resized composition equals one scaffolded at that size.** `lower-third` scaffolded at 480x270 and rendered at 270x480, and `end-card` at 270x480 and 360x360, decoded with libvpx at 0.3, 0.8 and 1.5 s: at most 0/255 apart from the same template scaffolded at the render size (the test allows 2/255). `pick()` therefore sees the format.
- **Cost.** A 2 s composition at 270x480 renders in about 5 s alone (10-30 s per pair while other suites ran); a format adds one render per generated clip on the single clip queue, as the Side effects say.
- **Limit.** Layout written in fixed pixels (a hand-written composition that places elements at `left: 1500px`) is not re-blocked by a new size: it needs fractions of `stage()` or `pick()`, as the templates use. The adapter changes the size, never the layout.

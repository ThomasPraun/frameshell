# Subtitle presets are shared rules; Archivo Black ships via npm

Subtitle cues, presets and layout live in one pure module, `@frameshell/schema/subtitles`, used by both the preview overlay and the export compiler, so both show the same words on the same frames with the same layout (#22, PR #94).

## Decision

- Presets: `big-keyword` (default: up to three large upper-case words, the spoken word highlighted, low in the frame) and `plain`. `position`: top, center or bottom. Presets are data; more can be added without schema changes.
- Words are derived, never copied: a subtitle track follows a video/audio track and shows the transcript words each followed clip keeps (midpoint rule, same as `transcribe --verify` and the transcript view), placed through clip start and speed; corrections come from the transcript `edits`.
- Export burns an ASS script generated by the compiler; cue edges are floored to the frames ffmpeg shows (property-tested at 24–60 fps). Text is sanitized (no braces, backslashes, newlines).
- Font: Archivo Black (SIL OFL 1.1) from the npm package `@expo-google-fonts/archivo-black`, so no binary is committed; export copies it into the job work dir and the preview loads the same file.

## Consequences

- A single word wider than the frame is not shrunk to fit (accepted for v0.1).
- `ui_state` / `ui.select` do not include a selected subtitle track yet (would be a protocol change).

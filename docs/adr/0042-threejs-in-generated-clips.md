# three.js in generated clips: a pinned bundle copied into HyperFrames compositions, rendered on SwiftShader

3D product shots, titles and logos for launch films ([#473](https://github.com/ThomasPraun/frameshell/issues/473), epic #451), the lighter 3D route beside Blender (ADR 0035). The owner chose option A of the proposal on #473 on 2026-11-11 with every recommendation, after a spike; the spike ([`docs/research/three-in-hyperframes.md`](../research/three-in-hyperframes.md), PR #531) was approved on 2026-11-13 with its five corrections, which this ADR records. Extends ADR 0033 (motion runtime); ADR 0033 is unchanged except a cross-link. **Slices 1 to 4 (with `title-3d` in slice 3b) and the motion blur cap of slice 5 are built; the rest of 5 is not.**

## Context (verified)

- ADR 0033: HyperFrames is the motion host. The motion runtime is copied into each composition on scaffold, frozen per clip and hashed as an input; `bind(id, paint)` registers a seek-only timeline and must be called synchronously. Templates (`hyperframes new --template`, `update`) and the core determinism verify (`clip.verify`, 12 probes cold vs reseek, 2/255) are built.
- The adapter hashes every file of the composition directory except `node_modules`, renders a copy in-process with `@hyperframes/producer` 0.9.30 and the managed `chrome-headless-shell` 154. The producer's GPU mode defaults to `software` (`--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`); `PRODUCER_BROWSER_GPU_MODE` can switch it to hardware GL.
- The daemon runs clip renders in their own queue, one at a time (`clipJobs`, concurrency 1). For a WebGL canvas the producer uses one capture worker and screenshots (`workerCount: 1`, static-frame dedup off).
- Spike (three 0.187.0, MIT, macOS arm64, pinned Chrome): the product shot paints in about 0.1 s and renders at 0.24 to 0.33 s per 1080p frame on a loaded machine; 12 probes cold vs reseek are byte-identical and two renders are byte-identical; alpha survives to VP9. Five findings changed the draft decision, below.

## Decision

1. **Own ADR, decision row 47 of the SPEC.** A third-party library in shipped plugin files, a GL-mode pin and new check rules.
2. **Vendored pinned bundle, no CDN.** `three` is an exact devDependency of `@frameshell/hyperframes`. `pnpm gen:three` (`plugins/hyperframes/scripts/build-three.mjs`) bundles the whole `three` namespace plus `RoomEnvironment`, `RoundedBoxGeometry`, `TextGeometry`, `FontLoader` / `Font`, `GLTFLoader` and `SVGLoader` (+29 KB) with esbuild into one minified classic IIFE that sets `window.THREE`, with the full MIT notice in its header, and writes it as a string to `plugins/hyperframes/src/three-runtime.ts`. The generator refuses any input outside the `three` package; a drift test reruns it with `--check`. The full namespace (782 KB raw, 200 KB gzip in the spike) is chosen over a curated list (666 KB) so a template or an agent never meets a missing class.
3. **Copied only into 3D compositions.** A template marked 3D (`ThreeTemplate`, `three: true`) gets `frameshell-three.js` next to `frameshell-motion.js` on `hyperframes new --template`, at the composition root (never under `node_modules`, which the cache key skips). `hyperframes update` refreshes it like the motion runtime: older Frameshell copies are replaced, an edited, newer or foreign file is kept unless `--force`.
4. **One clock.** The motion runtime's `bind`: `paint(t)` sets every pose from `t` and calls `renderer.render` once. `hyperframes check` adds `three_animation_loop` (`setAnimationLoop`) and `three_clock` (`THREE.Clock`, `getDelta`, `getElapsedTime`) as errors and `three_mixer_update` (`mixer.update(delta)`, use `setTime(t)`) as a warning; the linter already blocks `requestAnimationFrame` and `Math.random` in author code.
5. **Readiness through `window.__hf.buildReady` (correction 1).** In three 0.187 `LoadingManager` keeps its counters in closures, so the HyperFrames three adapter never waits on `THREE.DefaultLoadingManager`. A 3D composition puts one promise per asset group in `window.__hf.buildReady.<key>`, synchronously from its script: the 0.9.30 runtime holds `__renderReady` (render and live preview) until every promise settles, and a rejection is a startup error, so a missing model fails the render with its path. After the loads the page repaints the last time, since the live page gets no further seek.
6. **Soft shadows are VSM (correction 2).** r187 has no `PCFSoftShadowMap`; `PCFShadowMap` stays hard. Template defaults: VSM, 1024 map, radius 8, 8 blur samples, MSAA 4 (`antialias: true`), PMREM 256 from `RoomEnvironment`, neutral tone mapping. A ground of `ShadowMaterial` stays inside the shadow camera (past its edge VSM draws a dotted line). Never a 4096 map.
7. **No `TTFLoader` (correction 3).** It imports opentype.js from a CDN at run time and cannot be bundled. 3D text uses `TextGeometry` with a typeface JSON generated at build time (Archivo Black, OFL), or the existing font path for DOM text over the canvas. *As built (slice 3b):* the generator uses opentype.js, which stays out of the bundle.
8. **A 3D-aware check (correction 4).** The linter scans local scripts, and the bundle's own `Math.random` (UUIDs) and render loop (`WebGLAnimation`) would block every 3D composition. `check` drops findings located in a Frameshell three.js bundle (recognised by its header, any version) and the linter's `requestanimationframe_in_composition` while no other script of the composition calls `requestAnimationFrame`; the scene code is linted as before.
9. **SwiftShader for every HyperFrames render, one at a time (correction 5).** The adapter sets `PRODUCER_BROWSER_GPU_MODE=software` before each render, so no daemon environment flips a render to the machine's GPU. Clip renders stay serial (the clip queue), and the producer captures a canvas with one worker; a slow 3D clip delays other clip renders, as a Blender final does. Hardware GL may come later, opt-in only, if templates exceed the budget.
10. **Cost budget.** About 1 s per 1080p frame for a draft-quality product shot; above it, lower MSAA, the shadow map and PMREM size first, then reopen.
11. **No dedicated `three` clip type.** Revisit only if a template fails `clip.verify` or the cost budget on HyperFrames.
12. **Blender bridge.** A GLB exported from Blender is loaded by a three.js template from the composition directory (hashed like every file); no code link between the plugins. GLBs are plain glTF binary: the bundle has no Draco, KTX2 or Meshopt decoder.
13. **Motion blur (cross rule with #501).** A 3D composition with motion blur is capped at 8 fixed samples with a warning. *As built:* 3D means the composition holds `frameshell-three.js` or a script makes a WebGL renderer or context, so a hand-written scene is capped too.

### Settled in slices 1 and 2

- The bundle is 0.82 MB with the notice; `scripts/` is not published, `src/three-runtime.ts` builds into `dist`.
- `product-shot` (`plugins/hyperframes/src/templates/product-shot.ts`) on the shared studio of `templates/three-kit.ts` (renderer, PMREM, key, fill and rim light, ground, `ready`): the built-in rounded box or a GLB fitted to the same size, a label texture, finish presets, a push-in, a glint sweep, spin and orbit props, a DOM headline, layout per format through `M.pick`. Transparent unless `backdrop`.
- `plugins/hyperframes/test/three-real.test.ts` (opt-in) renders it with a generated GLB and a texture: the model is in the first frame, alpha is kept, `clip.verify` passes with tolerance 0, and a missing model fails the render naming the file. `templates-real` lays it out in the four formats.

### Settled in slice 3 (`logo-3d`)

- `plugins/hyperframes/src/templates/logo-3d.ts` on the same studio, finish presets (`FINISH_PRESETS`, `finishVariable`) and `load` helper (`loadScript`) that `three-kit.ts` now shares with `product-shot`, whose page is unchanged apart from the helper's whitespace. The bundle gains `SVGLoader` (`build-three.mjs` `ADDONS`).
- Input: an SVG inside the composition directory (`logo`, an `image` prop, so `hyperframes new --component <svg of brand show>` fills it); empty shows a built-in hexagon mark with a hexagonal hole. The page reads it with `FileLoader`, parses it with `SVGLoader`, and extrudes every filled path (`SVGLoader.createShapes`, `ExtrudeGeometry`, holes and even-odd fills included) into one centred group, 2 world units on its longer side, flipped on y with a negative scale. Strokes, text, images, gradients and `<use>` are not extruded: an SVG with no filled path fails the render naming the file, as does a path that is not `.svg` or a file that is missing (through `__hf.buildReady`, decision 5).
- Props: `depth` (fraction of the longer side), `bevel`, `colors` (`single` with `color`, or the SVG's own fills), `finish`, `reveal` (`rise`: the depth grows out of the flat logo, `turn`, `drop`), `spin`, an optional DOM headline, `size`, `shadows`, `backdrop`. Every pose is a function of `t` (springs of the motion runtime); the glint and the push-in are those of `product-shot`.
- The ground of the studio is turned into a wall 0.12 units behind the logo that only catches its shadow (`ShadowMaterial`, inside the shadow camera as decision 6 requires); the logo itself does not receive shadows (VSM bleeds on thin bevels).
- `three-real.test.ts` (opt-in) renders a generated two-colour SVG with a hole: both fills are in the first frame and the settled one, alpha is kept, `clip.verify` passes with tolerance 0, the three reveals paint the built-in mark, and a missing file, a raster and a stroke-only SVG fail naming the file. `templates-real` lays it out in the four formats.

### Settled in slice 3b (`title-3d`)

- **Converter: opentype.js 2.0.0** (MIT, Copyright 2020 Frederik De Bleser; the licence text of the published 2.0.0 package was read, and it has no dependencies), an exact devDependency of `@frameshell/hyperframes` that only `scripts/build-typeface.mjs` imports. It is in neither the three.js bundle (`build-three.mjs` still refuses any input outside the `three` package) nor the plugin's runtime dependencies, and a test pins both. facetype.js and converters of unclear licence are not used. The font comes from `@expo-google-fonts/archivo-black` 0.4.1, the package ADR 0006 already pins for the app and core, as a plugin devDependency.
- **Font licence:** Archivo Black is SIL OFL 1.1 (`LICENSE_FONT` of the package). Its copyright line, "Copyright 2017 The Archivo Black Project Authors", declares no Reserved Font Name, so a converted copy may be distributed and embedded; the generator throws if a later version of the package declares one. The generated file's header carries the copyright and licence ("converted outlines of Archivo Black"), and the plugin README lists both licences in its third-party notice.
- **Typeface:** `pnpm gen:typeface` writes `plugins/hyperframes/src/title-typeface.ts` (a string, with `--check` drift mode and a drift test like `gen:three`): three.js typeface JSON of resolution 1000 (outlines as `m`, `l`, `q`, `b` commands in whole numbers, per-glyph advance `ha`, ascender, descender) for ASCII, Latin-1 and the punctuation of everyday titles (en and em dash, curly quotes, bullet, ellipsis, `€`, `™`): 202 glyphs, 79 KB with the full licence text in `original_font_information`, ASCII-only escapes. A first key `frameshellTypeface` names its version (`TITLE_TYPEFACE_VERSION`; bump it when the glyph set or the conversion changes) the way a bundle header does. No kerning: the format has none.
- **A composition file:** `ThreeTemplate` gains `assets`, extra frozen files that scaffolding writes next to the bundle. `title-3d` writes `frameshell-title.typeface.json` at the composition root, so `inputs()` hashes it with the page and the bundles; `hyperframes update` refreshes it by the same rule as the bundles (older Frameshell copies replaced, edited, newer or foreign ones kept unless `--force`; `UpdateReport.typeface`). No change to the cache layout.
- **Template:** `plugins/hyperframes/src/templates/title-3d.ts` on the shared studio, `FINISH_PRESETS` (default `gloss`; `finishVariable` takes the default), `loadScript` and `ready`, and the motion runtime's springs and stagger. The page loads the JSON with `FileLoader`, builds a `Font` and one `TextGeometry` per distinct letter (`curveSegments` 6 for the software renderer), centred on its own middle, one mesh per drawn letter. Layout is done in the page from the typeface's advances: explicit `\n` lines (at most 3), words wrapped to the format's width, shrunk in steps down to 40 % until the widest line fits; a text that does not fit even then (more than 3 lines, or one word wider than the width) fails the render naming it. The title is at most 3.6 world units wide whatever the format, and the camera frames that as the format's share times `size`, so the studio's shadow wall and shadow camera always cover it; the width it may take is cut down to 90 % of the frame (4 % less for the end of the push-in) where `size` would pass it, and the block's height is cut to 80 % of the frame, or to the part above the headline. Props `text`, `subtitle`, `depth`, `bevel`, `colors` (`single`, `blend` into `color2`), `color`, `finish`, `reveal` (`letters`: per-letter spring stagger swing in; `rise`: the depth of the whole title grows out of the flat text; `drop`: per-letter fall with an alternating tilt), `spin`, `ink`, `size`, `shadows`, `bg`, `backdrop`. Every pose is a function of `t`; no random source.
- **Failures name the cause** through `__hf.buildReady` (decision 5): a missing typeface (the `load` helper names the file), a file that is not valid JSON or not a typeface, a character the typeface lacks (the character and its code point, never the `?` fallback or an empty box), more than three lines.
- **Tests:** unit tests for the JSON shape, three.js reading it (counters, advances), the drift check, the scaffold copy (title-3d only), `update`; `three-real` (opt-in) checks the letters in the first frame with a rising depth, alpha, `clip.verify` at tolerance 0 with the stagger arrival, every reveal, a wrapped long title, a colour blend and the four failure messages; `templates-real` lays `title-3d` out in the four formats with the other templates.

### Settled in slice 4

- The playbook is `plugins/hyperframes/skills/hyperframes/3d-playbook.md`, in the plugin skill beside `SKILL.md` (plugin skills are linked as a directory, so the page reaches the agent with it), linked from the skill's 3D section and from the motion-films page of the frameshell skill. It separates what the `product-shot` template does (studio, finishes, glint, push-in, creep) from what a hand-written scene adds (vignette, grain, parts that open, the full beat sheet), and names no command or template that does not exist: a 3D logo is the `logo-3d` template (an "A 3D logo" section) and, since slice 3b, a 3D title is the `title-3d` template (an "A 3D title" section), while other extruded text goes to DOM text over the canvas or a supplied GLB.
- `Chrome.launch` (`packages/core/src/inspect/chrome.ts`, the headless Chrome of `clip.verify`, `inspect.point` and brand capture) passes `--enable-unsafe-swiftshader` (`chromeLaunchArgs`, unit-tested), so a machine without a GPU still gets a WebGL context there instead of depending on the Chrome build's fallback.

## Consequences

- **Plugin size** grows by the bundle (0.82 MB raw in `dist`) and the title typeface (79 KB), and each 3D composition carries a copy, hashed on every key check; a `title-3d` composition also carries the typeface.
- **A re-pin is a deliberate PR:** bump `three`, `pnpm gen:three`, run the opt-in `three-real` and `templates-real` tests. Old clips keep their copy until `update`.
- **Pixels of existing clips** do not change: software GL was already the producer's default. Someone who had set `PRODUCER_BROWSER_GPU_MODE=hardware` now renders on SwiftShader; the GL mode is not in the cache key, so earlier hardware renders stay cached until something else changes.
- **Live preview** in the app runs WebGL on the GPU while export and `clip.verify` (core's Chrome launches with `--enable-unsafe-swiftshader`) do not: small shading differences between the live page and the export are expected (ADR 0010 already labels live clips).
- **Pick and element mode** see a 3D scene as one `<canvas>`: element mode moves or scales the whole picture; object changes are props.
- **Coupling to HyperFrames internals** grows: `window.__hf.buildReady` is an undocumented hook of the 0.9.30 runtime. `three-real` must pass on every HyperFrames bump.
- **Unchanged:** schema, JSON Schema, protocol (`PROTOCOL_VERSION`), plugin API, cache layout, core, desktop, the Remotion and Blender plugins.
- **Not covered by the spike:** Linux, Windows and other CPUs (SwiftShader runs generated CPU code), transmission, large GLBs against the producer's ready timeout (45 s).
